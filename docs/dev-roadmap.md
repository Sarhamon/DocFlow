# DocFlow 코드 개발 로드맵

> 기능명세서(`functional-spec.md`, 119개 기능)를 기준으로 코드를 **새로 짜는** 계획이다.
> 모듈 구조와 설계 결정(README 3·4·5장)은 유지하고 내부 구현을 다시 쓴다.
> 일정은 팀 규모·기한을 모르므로 날짜 대신 **규모(S/M/L)** 와 **순서·의존 관계**로 적었다.

---

## 1. 원칙

1. **유지하는 틀**: `docflow/{hwpx, schema, validate, adapters}` 모듈 분리, `forms → templates → schemas → out` 경로 미러링, COM 의존을 어댑터 한 곳에 격리, 규칙 코드 / LLM 역할 분담.
2. **아래에서 위로**: 문서 엔진(읽기·쓰기·검증·변환) → 서비스 → 인증 → 화면 → LLM 순서. 위 계층은 아래 계층의 인터페이스에만 의존한다.
3. **수직 슬라이스 먼저**: 화면을 만들기 전에 서식 3종으로 `입력 → 검증 → 주입 → 변환`을 코드로 끝까지 통과시킨다(M5). 여기서 설계가 틀리면 가장 싸게 고친다.
4. **합격 기준은 이전 측정값**: 아래 회귀 기준을 새 코드가 그대로 재현해야 해당 마일스톤이 끝난다.
5. **테스트는 내부 자료에 의존하지 않는다**: 단위 테스트는 코드로 만든 스키마·HWPX를 쓰고, 실제 서식(`forms/`)을 쓰는 회귀 테스트는 로컬 전용(`pytest -m local`)으로 분리한다.

### 회귀 기준 (이전 구현의 측정값)

| 항목 | 기준 |
|---|---|
| 템플릿 변환 | `.hwp` 193개 → `.hwpx` 193개, 실패 0 |
| 스키마 추출 | 서식 183개 전부 추출, 실패 0 (누름틀 630 / 표 2,501 / 슬롯 8,904 / 반복영역 281) |
| 채울 지점 | 슬롯·반복영역이 모두 0인 서식 0개 |
| 누름틀 파싱 | 기안문·품의서 계열 15개 서식에서 547개 / 고유 51종 |
| 검증 규칙 적용 | 필수 누락 177/183, 금액 합계 78/183, 날짜 95/183 |
| 쓰기 라운드트립 | 주입 → 저장 → 재읽기 값 일치 (누름틀 **+ 표 셀 + 반복영역**으로 확대) |
| 산출물 | 생성한 HWPX를 한글이 정상 열고 `.hwp`/`.pdf` 변환 성공 |

## 2. 마일스톤 개요

```
M0 기반 ─ M1 HWPX 코어 ─ M2 서식 파이프라인 ─ M3 검증 엔진 ─ M4 변환 어댑터
                                                         └──────────┬─────────┘
                                                                M5 수직 슬라이스 (CLI)
                                                                    │
                                                  M6 서비스·저장 ─ M7 인증(IAM)
                                                                    │
                                              ┌─────────────────────┴───────────────┐
                                        M8 사용자 화면                        M9 관리자 페이지
                                              └─────────────────────┬───────────────┘
                                                            M10 LLM 연동 ─ M11 문서 간 검증·운영 ─ M12 AWS 이전
```

| M | 이름 | 규모 | 기능명세 영역 | 끝났다는 증거 |
|---|---|:-:|---|---|
| M0 | 기반 | S | — | 테스트·린트가 한 명령으로 돈다 |
| M1 | HWPX 코어 | L | 문서 변환 > 값 주입 | 누름틀·표 셀·반복영역 라운드트립 통과 |
| M2 | 서식 파이프라인 | M | 서식 관리 > 서식 등록(백엔드), 템플릿 로딩 | 변환 193 / 추출 183, 실패 0 |
| M3 | 검증 엔진 | L | 입력 완료 검증, 오류 탐지(규칙) | 규칙 3종 + 제외 처리, 적용 서식 수 재현 |
| M4 | 변환 어댑터 | S | 문서 변환 > 형식 변환 | HWP·PDF 산출, 재시도·프로세스 정리 |
| M5 | 수직 슬라이스 | M | 위 전부의 통합 | 서식 3종이 CLI로 입력→산출까지 통과 |
| M6 | 서비스·저장 | L | 저장·다운로드, 서식선택(백엔드), 정보입력(임시저장) | API로 문서 생성·저장·재조회 |
| M7 | 인증(IAM) | M | 인증·권한, 계정 관리 | 발급 계정으로만 로그인, 역할 분기 |
| M8 | 사용자 화면 | L | 서식선택, 정보입력, 입력 완료 검증, 오류 탐지, 문서 수정, 저장·다운로드, 내 문서함 | 사용자가 브라우저로 문서 1건 완성 |
| M9 | 관리자 페이지 | L | 관리자 전체(운영 현황 일부 제외) | 관리자가 새 서식을 올려 사용자 화면에 노출 |
| M10 | LLM 연동 | M | 본문 초안 생성, 정성 판정 | 초안 생성·인용 검사, 체크리스트 판정 |
| M11 | 문서 간 검증·운영 | M | 문서 간 검증, 운영 현황, 감사 로그 | 대조 규칙 동작, 통계·로그 조회 |
| M12 | AWS 이전 | M | 비기능(이전성) | COM 워커 분리 후 동일 동작 |

## 3. 마일스톤 상세

### M0. 기반 (S)
- 패키지·테스트·린트 설정, 설정 파일(경로·환경 분리), 로깅.
- 테스트 구분: 기본(내부 자료 없이) / `local`(실제 서식 필요) 마커.
- 이전 구현의 측정값을 회귀 기준으로 문서화 (위 표).
- **완료**: `pytest`가 클론 직후 통과한다.

### M1. HWPX 코어 (L) — 가장 먼저, 가장 중요
- 읽기: 누름틀, 표(좌표·병합·중첩), 셀 텍스트.
- 쓰기: **누름틀, 표 셀, 반복영역(행 추가 포함)**. 서식 대부분이 표라 이번 재작성의 핵심 과제다.
- 저장 규격: `mimetype` 첫 항목·무압축 유지.
- 설계 결정: 병합 셀에 쓸 때의 규칙, 반복영역 행이 부족할 때 행 복제 방식, 줄바꿈·특수문자 처리.
- **완료**: 대표 서식에서 쓰기 → 저장 → 재읽기 값 일치, 한글에서 정상 열림(M4 이후 재확인).

### M2. 서식 파이프라인 (M)
- `convert_templates`(HWP→HWPX, 한컴 COM)와 `extract_schema` 재작성.
- 스키마 모델 재정의: 필드·표·슬롯(placeholder/empty)·반복영역(+capacity)·결재란 구분.
- 자리표시자 판정(`is_placeholder` 등)을 순수 함수로 분리, 단위 테스트로 고정.
- 서식 번호·사업·카테고리 파싱, 사업별 카테고리 이름 통합 처리.
- **완료**: 회귀 기준 중 변환 193 / 추출 183 / 채울 지점 누락 0.

### M3. 검증 엔진 (L)
- `Issue` 모델: 규칙 코드, 심각도(오류/경고), 위치(표·셀·누름틀), 사유, 조치 문구.
- 규칙: `REQUIRED_EMPTY`, `AMOUNT_TOTAL_MISMATCH`, `DATE_INVALID`, `DATE_ORDER`.
- 오탐 제외(결재란, 반복영역 내부, 이름 없는 수식 누름틀, 항목명 추정 빈 칸)를 규칙 설정으로 명시.
- 인터페이스를 **칸 단위 호출**과 **문서 전체 호출** 두 가지로 설계 (실시간 점검 / 완료 검증이 같은 규칙을 공유).
- 규칙 on/off·서식별 예외를 설정으로 받을 수 있게 (관리자 규칙 관리 대비).
- **완료**: 적용 서식 수(177/78/95) 재현, 오탐 사례 테스트 보존.

### M4. 변환 어댑터 (S)
- HWPX → HWP / PDF, 변환 실패 1회 재시도, 한글 프로세스 추적·정리.
- 변환 호출을 **작업 요청/결과 인터페이스**로 감싸 M12에서 워커 분리가 가능하게 한다(지금은 같은 프로세스 호출).
- **완료**: 산출물이 한글에서 열리고, 비정상 종료 후에도 다음 변환이 멈추지 않는다.

### M5. 수직 슬라이스 (M)
- 서식 3종 선정: **기안문(누름틀 중심)**, **표 중심 서식**, **반복영역+합계 서식(예: 교통비 내역서)**.
- CLI/스크립트로 `서식 로딩 → 값 입력 → 검증 → 주입 → HWP/PDF` 통과.
- 이 단계에서 M1~M4의 인터페이스 불편을 모아 수정한다.
- **완료**: 3종 모두 통과, 검증 오류를 일부러 넣으면 위치·사유가 정확히 나온다.

### M6. 서비스·저장 (L)
- 웹 프레임워크(FastAPI)와 저장소: 서식 목록·검색, 새 문서 만들기, 임시저장·불러오기, 문서 상태, 산출물 파일 저장, 이력(입력값·통과 규칙·**서식 버전**).
- 문서 소유자를 계정에 연결할 수 있는 모델(M7 대비).
- 서식 버전: 신규는 최신, 기존 문서는 작성 당시 버전 유지.
- **완료**: API만으로 문서 생성 → 저장 → 재조회 → 산출물 다운로드.

### M7. 인증(IAM) (M)
- 계정 발급(아이디·초기 비밀번호), 최초 로그인 비밀번호 변경 강제, 비밀번호 초기화, 비활성화·삭제.
- 로그인 실패 잠금, 세션 만료, 역할(사용자/관리자) 분기, 문서 소유자 기준 접근 제어.
- 사업별 접근 제한은 **만들지 않는다**.
- **완료**: 발급된 계정으로만 로그인, 타인 문서 접근 차단, 관리자 전용 경로 차단.

### M8. 사용자 화면 (L)
- 서식 선택(목록·검색·미리보기), 정보 입력(누름틀·표·반복영역, 엑셀 붙여넣기, 자동 임시저장).
- 실시간 점검(형식·중복·미리 합계), 입력 완료 검증, 오류 목록(위치 이동·사유·조치), 수정·재검증.
- 변환·다운로드, 내 문서함(작성 중·완료·이력).
- **완료**: 사용자가 브라우저에서 서식 1건을 처음부터 끝까지 완성하고 내려받는다.

### M9. 관리자 페이지 (L)
- 서식 등록(업로드 → 자동 변환 → 스키마 추출 → 결과 확인), 서식 수정·공개·개정(버전).
- 입력폼 관리(항목 승인·순서·필수·형식), 카테고리·항목명(한글 표시명) 매핑.
- 검증 규칙 관리(on/off·예외), 계정 관리 화면, 시스템 설정(LLM·변환 워커 상태).
- **완료**: 관리자가 새 서식을 올려 승인하면 사용자 화면에 나타나고 문서를 만들 수 있다.

### M10. LLM 연동 (M)
- 로컬 LLM 실행 환경(EXAONE 3.5), 프롬프트 구성(개인정보 제외), 초안 생성, 숫자·날짜 인용 검사, 채택/수정/재생성.
- 정성 판정: 체크리스트 기반, 근거 문장 제시. 규칙 코드와 결과를 같은 오류 목록에 합친다.
- **완료**: 초안의 숫자가 입력값과 어긋나면 경고가 나온다. 같은 입력 대비 규칙 검증 결과가 LLM 때문에 달라지지 않는다.

### M11. 문서 간 검증·운영 (M)
- 문서 간 금액 일치 (대조 서식 쌍 확정 후), 문서 현황·오류 통계·로그인 이력·감사 로그.
- **완료**: 계획서-정산서 금액 불일치를 잡고, 관리자가 통계와 로그를 조회한다.

### M12. AWS 이전 (M)
- 한컴 COM 워커를 Windows 인스턴스로 분리(M4의 요청/결과 인터페이스 사용), 웹/LLM 컴퓨팅 분리, 저장소·DB 이전.
- **완료**: 로컬과 동일한 시나리오가 AWS에서 통과한다.

## 5. 핵심 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| **표 셀 쓰기** (병합·반복행 복제) | 서식 대부분이 표라 막히면 전체가 막힘 | M1을 가장 먼저, 서식 3종으로 조기 검증 |
| 한컴 COM 불안정 (좀비 프로세스, 무한 대기) | 변환 중단 | 프로세스 추적·정리, 타임아웃, 재시도(M4) |
| 로컬 LLM 품질·속도 (RTX 3060 12GB) | 초안 품질 부족 | M10을 뒤로 미루고, 초안 없이도 서비스가 완결되게 설계 |
| 새 서식 유형에서 주입 실패 | 일부 서식만 동작 | 신규 카테고리 표본으로 주입·변환 확인(회귀 `local` 테스트) |
| 로그인 도입이 기획에 없던 범위 | 일정 증가 | 팀 합의 필요. 제외 시 M7·내 문서함·계정 관리 제거 |
| 서식 개정 시 기존 문서 호환 | 이력 훼손 | 문서에 서식 버전 기록(M6) |

## 6. 정해야 할 것 (제안 포함)

| 항목 | 제안 | 비고 |

| 웹 화면 방식 | 서버 렌더링(Jinja2) + HTMX | 팀 프론트엔드 경험에 따라 SPA도 가능 |
| DB | SQLite → 이전 시 RDS | M12 대비 ORM 사용 |
| 비밀번호 저장 | argon2 또는 bcrypt 해시 | |
| 세션 | 서버 세션 쿠키 | |
