# DocFlow 코드 개발 로드맵

> 기능명세서(`functional-spec.md`, 127개 기능)를 기준으로 코드를 **새로 짜는** 계획이다.
> 모듈 구조와 설계 결정(README 3·4·5장)은 유지하고 내부 구현을 다시 쓴다.
> 일정은 팀 규모·기한을 모르므로 날짜 대신 **규모(S/M/L)** 와 **순서·의존 관계**로 적었다.

---

## 1. 원칙

1. **유지하는 틀**: `docflow/{hwpx, schema, validate, adapters}` 모듈 분리, `forms → templates → schemas → out` 경로 미러링, COM 의존을 어댑터 한 곳에 격리, 규칙 코드 / LLM 역할 분담.
2. **아래에서 위로**: 문서 엔진(읽기·쓰기·검증·변환) → 서비스 → 인증 → 화면 → LLM 순서. 위 계층은 아래 계층의 인터페이스에만 의존한다.
3. **수직 슬라이스 먼저**: 화면을 만들기 전에 서식 3종으로 `입력 → 검증 → 주입 → 변환`을 코드로 끝까지 통과시킨다(M5). 여기서 설계가 틀리면 가장 싸게 고친다.
4. **합격 기준은 이전 측정값**: 아래 회귀 기준을 새 코드가 그대로 재현해야 해당 마일스톤이 끝난다.
5. **테스트는 내부 자료에 의존하지 않는다**: 단위 테스트는 코드로 만든 스키마·HWPX를 쓰고, 실제 서식(`forms/`)을 쓰는 회귀 테스트는 로컬 전용(`pytest -m local`)으로 분리한다.

```

                                                                M5 수직 슬라이스 (CLI)
```

**진행 현황 (2026-10-31)**: M0~M11 완료. M10 은 실제 모델(EXAONE 3.5, RTX 3060)로 완료 기준을 확인했고
브라우저에서 글로 채우기 → 본문 초안 → 문서 만들기까지 써 봤다. 남은 것은 M12(AWS 이전).
규모(S=1, M=2, L=3) 가중 30점 중 28점, **93%**.
테스트 695개(기본 672 + `local` 23) 통과.
세부 수치는 [`index.html`](index.html) 에 있다.

**순서 (2026-10-24)**: 정보 입력의 기본 방식을 **프롬프트 → LLM 이 칸을 채움 → 사용자가 확인**으로 바꿨다.
칸을 하나씩 채우는 M8 화면은 확인·수정 화면이자 LLM 을 못 쓸 때의 대체 경로로 남는다. 그래서 M10 을 먼저 하려 했으나,
LLM 을 돌릴 GPU 장비(RTX 3060)가 개발 PC 에 없어 **M9 → M11 → M10 의 LLM 없는 부분** 순서로 진행했다.
M10 의 LLM 부분(자연어 일괄 입력·본문 초안·정성 판정)은 GPU 장비(RTX 3060)에서 확인했다(2026-10-31).

## 3. 마일스톤 상세

### M0. 기반 (S)
- 패키지·테스트·린트 설정, 설정 파일(경로·환경 분리), 로깅.
- 테스트 구분: 기본(내부 자료 없이) / `local`(실제 서식 필요) 마커.
- 이전 구현의 측정값을 회귀 기준으로 문서화 (위 표).
- **완료**: `pytest`가 클론 직후 통과한다.

### M1. HWPX 코어 (L) — 가장 먼저, 가장 중요
- 읽기: 누름틀, 표(좌표·병합·중첩), 셀 텍스트.
- 쓰기: **누름틀, 표 셀, 반복영역(행 추가 포함)**. 서식 대부분이 표라 이번 재작성의 핵심 과제다.
- 저장 규격: `mimetype` 첫 항목·무압축 유지.
- 설계 결정: 병합 셀에 쓸 때의 규칙, 반복영역 행이 부족할 때 행 복제 방식, 줄바꿈·특수문자 처리.
- **완료**: 대표 서식에서 쓰기 → 저장 → 재읽기 값 일치, 한글에서 정상 열림(M4 이후 재확인).

### M2. 서식 파이프라인 (M)
- `convert_templates`(HWP→HWPX, 한컴 COM)와 `extract_schema` 재작성.
- 스키마 모델 재정의: 필드·표·슬롯(placeholder/empty)·반복영역(+capacity)·결재란 구분.
- 자리표시자 판정(`is_placeholder` 등)을 순수 함수로 분리, 단위 테스트로 고정.
- 서식 번호·사업·카테고리 파싱, 사업별 카테고리 이름 통합 처리.
- **완료**: 회귀 기준 중 변환 193 / 추출 183 / 채울 지점 누락 0.

### M3. 검증 엔진 (L)
- `Issue` 모델: 규칙 코드, 심각도(오류/경고), 위치(표·셀·누름틀), 사유, 조치 문구.
- 규칙: `REQUIRED_EMPTY`, `AMOUNT_TOTAL_MISMATCH`, `DATE_INVALID`, `DATE_ORDER`.
- 오탐 제외(결재란, 반복영역 내부, 이름 없는 수식 누름틀, 항목명 추정 빈 칸)를 규칙 설정으로 명시.
- 인터페이스를 **칸 단위 호출**과 **문서 전체 호출** 두 가지로 설계 (실시간 점검 / 완료 검증이 같은 규칙을 공유).
- 규칙 on/off·서식별 예외를 설정으로 받을 수 있게 (관리자 규칙 관리 대비).
- **완료**: 적용 서식 수(177/78/95) 재현, 오탐 사례 테스트 보존.
  → 실제로는 v2 기준(필수 183 / 날짜 107 / 금액 합계 49)으로 고정하고, 올바른 입력에서 오탐 0을 확인했다.

### M4. 변환 어댑터 (S)
- HWPX → HWP / PDF, 변환 실패 1회 재시도, 한글 프로세스 추적·정리.
- 변환 호출을 **작업 요청/결과 인터페이스**로 감싸 M12에서 워커 분리가 가능하게 한다(지금은 같은 프로세스 호출).
- **완료**: 산출물이 한글에서 열리고, 비정상 종료 후에도 다음 변환이 멈추지 않는다.

### M5. 수직 슬라이스 (M)
- 서식 3종 선정: **기안문(누름틀 중심)**, **표 중심 서식**, **반복영역+합계 서식(예: 교통비 내역서)**.
- CLI/스크립트로 `서식 로딩 → 값 입력 → 검증 → 주입 → HWP/PDF` 통과.
- 이 단계에서 M1~M4의 인터페이스 불편을 모아 수정한다.
- **완료**: 3종 모두 통과, 검증 오류를 일부러 넣으면 위치·사유가 정확히 나온다.
  → 3종은 일반기안문(AID 1-01~10, 변형 1-03호), 정산서(AID 3-01), 교통비 지급 내역서(AID 5-05).
  `tools/make_document.py` 로 입력 → 검증 → HWPX → HWP·PDF 를 통과했고, 서식 183개의 변형 230건 전부를
  올바른 입력으로 만들어 오류 0. 입력 예시는 `examples/ysu_forms/m5/` (내부 서식 이름이 있어 커밋 제외).
  - 생성 규칙: 결재란 잔여값 비우기, 쓰지 않은 반복 행 비우기(미리 적힌 연번·금액 포함), 예시 항목 행 비우기,
    수식 재계산, 고른 변형만 남기기, 쓰지 않은 자리에 남은 자리표시자는 경고.
  - 고친 결함: `SUM(ABOVE)` 가 빈 칸에서 멈춤(수식 표시값 일치 220 → 304/305), 수식이 읽는 빈 칸을
    글 칸으로 잡음(131칸을 금액으로), 여러 문단 본문 누름틀 쓰기, 글자 모양이 나뉜 문구 치환.

### M6. 서비스·저장 (L)
- 웹 프레임워크(FastAPI)와 저장소: 서식 목록·검색, 새 문서 만들기, 임시저장·불러오기, 문서 상태, 산출물 파일 저장, 이력(입력값·통과 규칙·**서식 버전**).
- 문서 소유자를 계정에 연결할 수 있는 모델(M7 대비).
- 서식 버전: 신규는 최신, 기존 문서는 작성 당시 버전 유지.
- **완료**: API만으로 문서 생성 → 저장 → 재조회 → 산출물 다운로드.
  → FastAPI(`docflow/web/app.py`) + SQLAlchemy/SQLite + 로컬 파일 저장소(`data/`, 커밋 제외).
  서식은 `tools/sync_forms.py` 로 등록하고 템플릿이 바뀌면 버전을 쌓는다(버전마다 템플릿·스키마 보관).
  완료 문서는 고치지 않고 복제해서 고친다. 변환이 일부 실패하면 HWPX 를 보존하고 작성 중으로 두며,
  다시 만들면 다음 판이 된다. 한컴 변환은 한 번에 하나만 돈다(창 없는 한글 정리가 다른 요청을 끄지 않도록).

### M7. 인증(IAM) (M)
- 계정 발급(아이디·초기 비밀번호), 최초 로그인 비밀번호 변경 강제, 비밀번호 초기화, 비활성화·삭제.
- 로그인 실패 잠금, 세션 만료, 역할(사용자/관리자) 분기, 문서 소유자 기준 접근 제어.
- 사업별 접근 제한은 **만들지 않는다**.
- **완료**: 발급된 계정으로만 로그인, 타인 문서 접근 차단, 관리자 전용 경로 차단.
  → `docflow/service/auth.py` + `/api/auth/*`·`/api/admin/users/*`, 루트 관리자는 `tools/manage_users.py`.
  정책(비밀번호 규칙, 3회 실패 잠금, 30분 세션·연장·5분 자동 연장, 중복 로그인 차단)은 기능명세 1.1.
- 미룬 것: `documents.owner_id` 외래 키·NOT NULL, `document_events.actor_id`. 지금 `create_all` 은 있는

### M8. 사용자 화면 (L)

  금액 형식 `AMOUNT_INVALID`, 학번 중복 `ROW_DUPLICATE`.

  - 브라우저 확인(2026-10-24): 교통비 명단 붙여넣기·학번 중복·금액 형식 경고·오류 칸 이동·자동 저장·HWP/PDF,

### M10. LLM·입력 자동화 (L)
- 로컬 LLM 실행 환경(EXAONE 3.5, Ollama). RTX 3060 12GB 기준 7.8B 4bit.
- **자연어 일괄 입력**: 서식의 채울 칸 목록 → JSON 스키마 제약 출력 → 입력 화면에 채워 보여 주고 확인 후 반영.
  채운 금액·날짜가 프롬프트에 없으면 경고(인용 검사). 고른 서식의 칸만 넘긴다.
- **명단 가져오기**: 학생이 낸 입금계좌 확인서 HWP 여러 개 → HWPX 변환 → 4-01호 스키마로 명단 읽기 → 열 이름으로 맞춰 넣기.
  LLM 을 거치지 않는다. 종이로 받은 명단은 직접 입력(OCR 안 함).
- **개인정보**: 명단·계좌·주민등록번호는 LLM 에 넘기지 않는다. 주민등록번호는 암호화해 저장한다.
  계좌번호·주민등록번호 형식, 예금주-성명 불일치 경고 규칙을 더한다.
- 본문 초안: 프롬프트 구성, 초안 생성, 숫자·날짜 인용 검사, 채택/수정/재생성.
- 정성 판정: 체크리스트 기반, 근거 문장 제시. 규칙 코드와 결과를 같은 오류 목록에 합친다.
- **완료**: 프롬프트 하나로 서식 3종의 칸이 채워지고, 프롬프트에 없는 숫자는 경고가 나온다. 입금계좌 확인서 HWP 로
  명단이 채워진다. 같은 입력 대비 규칙 검증 결과가 LLM 때문에 달라지지 않는다.
  → LLM 없는 부분 완료 (2026-10-24):
  - 명단 가져오기(`docflow/service/roster.py`, `POST /api/documents/{id}/roster`): 칸 좌표가 아니라 **머리줄 이름으로
    열의 뜻**(성명·은행·계좌·주민등록번호·학번 …)을 찾는다. 한 줄·두 줄 머리를 모두 읽고, 예시 줄(`000`·`홍길동`)·빈 줄·
    합계 줄은 뺀다. 같은 사람(성명·계좌)은 한 번만. 저장하지 않고 미리 보여 준 뒤 사용자가 넣는다. 받는 명단에 없는 열

  - 주민등록번호 암호화(`docflow/service/crypto.py`): 입력값·이력 사본은 DB 칸 타입 `Encrypted`(AES-256-GCM),
    만든 HWPX·HWP·PDF 는 파일째 암호화하고 내려받을 때만 푼다. 관리자 열람 화면은 뒷자리를 가린다.

    본문·목적 같은 서술형 칸은 옮겨 적지 않고(빈 칸이나 글 전체가 들어갔다, 실측) 이어서 본문 초안이 쓴다

  - 본문 초안(`service/draft.py`, `POST /api/documents/{id}/draft`, DR_01~08): 기안문 본문과 서술형 글 칸(목적·배경 …).
    채운 입력값을 넘기되 명단은 인원·금액 합계만(코드가 더한다). 초안의 금액·날짜·인원이 입력값에 없으면
    `DRAFT_UNCITED`. 채택하면 입력값 `_drafted` 에 근거를 적고, 실시간 점검·검증이 LLM 없이 인용 검사를 다시 돈다.
  - 정성 판정(`service/review.py`, ER_05·06): 관리자가 체크리스트(`checklist_items`, 모든 서식 공통 또는 서식별,
    관리자 메뉴 **정성 판정**)를 정하면, 사용자가 편집 화면에서 눌러(`POST /api/documents/{id}/review`) 물음마다 적합·부적합·판단 불가와 근거를 받는다.
    근거 문장은 입력값에서 직접 찾아 칸을 가리키고, 못 찾으면 그렇게 알린다. 부적합·판단 불가는 `QUALITATIVE`
    경고로 같은 오류 목록에 들어가고, 문서 만들기를 막지 않으며 이력에 남기지 않는다.
  - 같은 날 고친 것(스키마 v4): 표 안의 제출 문장(`… 20○○년 ○○월 ○○일 … ○ ○ ○ (날인)`)은 문장을 두고 날짜·이름만

    표 칸을 입력 칸으로 바꿀 수 있다(AD_09, `origin="example"`, 비워 두면 예시를 지운다). 명단 열도 사용을 끄면
    `fixed`(서명 열 등). 학과용·부서용 사본 표는 원본 표 값을 그대로 쓴다(`pipeline.copy_map`). `결재` 칸이 있는
    행은 직위 이름과 상관없이 결재란으로 본다(`담당교수`).

    (일반기안문 9초 — 본문 초안 포함, 정산서 12초, 교통비 3초). 프롬프트에 없는 숫자·낱말은 경고, 정성 판정 3문항 5초.
    실측으로 고친 것:
    - 답 다듬기: 칸 이름에서 끌려온 낱말(`[세부과제명]`, `Activity명`), 형식 표시(`[text]`), 다른 칸 이름,
      글에 없는 '정보 없음' 표시(`미지정`·`기타`·`추가 설명 필요`)를 버린다.
    - 금액의 행·열(`place_amounts`): 표의 금액은 글에서 그 금액 앞의 항목 이름이 행, 같은 문장의 가장 가까운
      `예산`·`집행` 이 열이다. 다른 칸에 넣었으면 맞는 칸으로 옮기고, 하나로 정해지지 않으면 경고.
      정산서 금액 12칸 중 맞은 칸 7 → 11 (남은 1칸은 `예산 500,000원을 전부 집행` 의 집행 칸).
    - 본문 초안의 붙임: 글에 없는 첨부 문서를 지어내 지시문에 넣고 `DRAFT_UNCITED` 로도 잡는다.
      `끝.` 은 서식 본문 예시에 있는 공문 끝 표시라 둔다.
    - 본문 초안에 연락처 칸(전화·팩스·전자우편·주소·홈페이지 …)을 넘기지 않는다. 넘기자 본문 끝에
      `문의 : 031-441-0000 | 웹사이트 : …` 줄을 지어 붙였다.
  - 브라우저 확인(2026-10-31): 글로 채우기 → 본문 초안 → HWP 생성까지 사용자가 써 봤다. 그 과정에서 나온 것:
    - **문서번호·시행일자·접수번호·접수일자**는 결재 시스템이 시행할 때 매기므로 필수가 아니다(관리자가 정하면 필수).
      비워 두면 산출물에서 `○○○○처-000000` 을 지운다 (`schema.rules.ISSUED_FIELDS`).
    - **계정 정보로 칸 채우기**(`service/profile.py`): 새 문서의 빈 칸 가운데 학과/부서명·소속, 전화·연락처,
      팩스, 전자우편 칸을 계정의 부서·연락처·이메일로 채운다(팩스는 연락처와 같은 번호). 칸 이름 **전체**가
      맞을 때만 채운다(`강사 연락처`·`참여학과` 는 아님). 글로 채우기는 글에 없는 값을 지어내지 않으므로 계정에서 가져온다.
    - **결재란 중첩 표**(스키마 v5): 기안문 결재란의 `담당`·`PM 과장`·`처장` 칸 옆에 `○○○` 하나짜리 표가 들어 있어
      이름 없는 칸으로 잡혔다. 중첩 표의 이름 없는 칸은 그 표를 담은 바깥 칸의 이름을 쓴다(서식 183개의 중첩 표
      입력 칸 399개 모두 이름이 붙음). 표마다 바깥 칸 위치를 `hwpx.Table.host` 로 안다.
    - **붙임 문서**(`service/attachments.py`, 표 `document_attachments`): 기안문 본문의 `붙임 … 사업 계획서 1부.` 는
      따로 만드는 계획서를 가리킨다(묶음 파일을 나눠서 빠진 것이 아니다 — 원래 파일에도 없다). 기안문·지출품의서
      작성 화면에서 내 다른 문서를 순서대로 붙이고(`/api/documents/{id}/attachments`), 기안문과 붙임의 마지막 판을
      zip 하나로 받는다(`/bundle/{형식}`, `붙임1_…`; 붙임에 그 형식 파일이 없으면 받지 않고 알린다).
      본문의 붙임 줄은 붙인 문서로 다시 쓴다(`붙임  1. … 1부.` 공문 표기). 붙이거나 뺄 때, 본문 초안·글로 채우기
      직후에 고치고 [본문 붙임 줄 채우기] 단추도 있다. LLM 은 붙인 문서를 알려 줘도 `붙임 참조` 로 어림했다(실측).
      붙인 문서가 있으면 본문의 붙임은 인용 근거가 있다(경고하지 않음).
    - **복제**하면 입력값과 함께 붙임 문서·대조용 연결 문서도 넘어간다. 연결 상대는 나중에 이은 복제본을 본다
      (원본 완료 문서의 연결은 그대로, 복제본을 지우면 원본으로 돌아간다).

### M11. 문서 간 검증·운영 (M)
- 문서 간 금액 일치 (대조 서식 쌍 확정 후), 문서 현황·오류 통계·로그인 이력·감사 로그.
- **완료**: 계획서-정산서 금액 불일치를 잡고, 관리자가 통계와 로그를 조회한다.
  → 완료 (2026-10-24, 브라우저 확인). API 는 `docflow/web/admin_ops.py`.
  - 감사 로그(`audit_logs`): 계정·서식·입력폼·카테고리·규칙·대조 규칙·시스템 변경, 문서 열람·내려받기. 비밀번호는 적지 않는다.
  - 문서 현황: 관리자는 목록(작성자·서식·상태·마지막 검증의 오류 수)만 본다. 입력값·파일은 **사유를 5자 이상 적어야**
    열람·내려받기가 되고 사유와 함께 감사 로그에 남는다 (명세 8장 결정).
  - 오류 통계: 기간별 검증 횟수·실패율, 규칙별·서식별(상위 10)·날짜별. 검증할 때마다 센다.
  - 로그인 이력: 성공·실패(비밀번호 틀림·잠김·없는 아이디)를 아이디·결과·날짜로 거른다.
  - 문서 간 대조(`cross_rules`·`document_links`): 관리자가 "기준 서식 항목들의 합 ↔ 대상 서식 항목들의 합" 규칙을
    등록한다(같아야 / 넘지 않아야). 사용자는 작성 화면의 **연결 문서**에서 자기 상대 문서를 잇고, 어긋나면 양쪽에서
    `CROSS_AMOUNT_MISMATCH` 경고. 수식 합계 칸은 입력이 아니라 고를 수 없어 항목 칸들을 더한다. 대상 서식 쌍은 아직 0개
    (쌍이 정해지면 관리자가 등록).

### M12. AWS 이전 (M)
- 한컴 COM 워커를 Windows 인스턴스로 분리(M4의 요청/결과 인터페이스 사용), 웹/LLM 컴퓨팅 분리, 저장소·DB 이전.
- **완료**: 로컬과 동일한 시나리오가 AWS에서 통과한다.

## 6. 정해야 할 것 (제안 포함)

| 항목 | 제안 | 비고 |
|---|---|---|
| 웹 화면 방식 | 서버 렌더링(Jinja2) + HTMX | 팀 프론트엔드 경험에 따라 SPA도 가능 |
| DB | SQLite → 이전 시 RDS | **결정(M6)**: SQLAlchemy 2.0 |
| 비밀번호 저장 | argon2 또는 bcrypt 해시 | **결정(M7)**: scrypt (표준 라이브러리, 같은 등급) |
| 세션 | 서버 세션 쿠키 | **결정(M7)**: 서버 세션 쿠키, 30분 + 연장 버튼 |
| 파일 저장 | 로컬 디렉터리 → 이전 시 S3 | **결정(M6)**: `FileStore` 인터페이스 |
| 수직 슬라이스 서식 3종 | 일반기안문 1-03호, 정산서(AID 3-01), 교통비 지급 내역서 | **M5에서 사용** |
| 로그인 도입 | 도입(IAM, 사업 제한 없음) | **결정**: 루트 관리자 1개 + 관리자 + 사용자 |
| 실시간 중복 체크 범위 | 반복 행의 학번 | **결정(M8)**: 학번만(성명은 동명이인). 문서번호 중복은 미정 |
| 본문의 작성일·서명란 | 작성일을 만든 날로 자동 채움 | 230건 중 130건에 `20○○년 ○○월 ○○일`·`○ ○ ○` 가 남는다(M5). 지금은 경고 + `replace`. 표 안의 제출 문장은 날짜·이름만 고치는 칸으로 잡고 남으면 `FILL_LEFT` 경고(2026-10-27) |
| 서식 제목 줄 | 산출물에서 지움 | `[ AID 서식 1-03호 ] <… - 부서용>` 같은 안내 줄 |
| 금액 칸 형식 검사 | 규칙 추가(명세 IN_15) | **결정(M8)**: `AMOUNT_INVALID` 경고 (입력은 막지 않음) |
| 정보 입력 방식 | 프롬프트 → LLM 채움 → 확인 | **결정(2026-10-24)**: 입력 화면은 확인·대체 경로. GPU 장비가 없어 M9·M11 을 먼저 |
| 명단·계좌 입력 | 입금계좌 확인서 HWP 업로드 / 직접 입력 | **결정(2026-10-24)**: LLM 에 넘기지 않음, OCR 안 함 |
| 묶음 파일 | 서식 번호마다 따로 목록에 | **결정(M8)**: 머리 번호 표시로 나눔, 갈래는 이름 뒤에(`(선대응)`) |
| 입력폼 관리 방식 | 추출 결과를 승인·조정 | **결정(M9)**: 항목별 사용·이름·형식·필수·순서만 조정 (명세 8장 #3 권장안) |
| 관리자 문서 열람 범위 | 목록 + 사유 입력 후 열람 | **결정(M11)**: 열람·내려받기는 사유와 함께 감사 로그. 열람 화면은 주민등록번호 가림 |
| 문서 간 대조 | 관리자가 서식 쌍을 등록하는 틀 | **결정(M11)**: 같아야 / 넘지 않아야, 경고. 실제 서식 쌍은 미정 |
| 개인정보 암호화 범위 | 입력값 + 만든 파일 | **결정(2026-10-24)**: AES-256-GCM, 키는 환경변수 또는 `secrets/data.key` |
| 문서번호·시행일자 | 결재 시스템이 매김 | **결정(2026-10-31)**: 필수 아님. 비우면 산출물에서 자리표시자를 지운다 |
| 작성자 정보 칸 | 계정 정보로 채움 | **결정(2026-10-31)**: 부서·연락처·이메일(관리자가 계정에 적음). 팩스는 연락처와 같은 번호 |
| 붙임 문서 | 기안문에 내 문서를 이어 둠 | **결정(2026-10-31)**: 순서대로 붙이고 zip 으로 함께 받기, 본문 붙임 줄 자동. 묶음 나누기는 유지 |
| 복제할 때 넘길 것 | 입력값 | **결정(2026-10-31)**: 입력값 + 붙임 문서 + 대조용 연결 문서 |
