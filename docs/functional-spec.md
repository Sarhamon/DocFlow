# DocFlow 기능명세서

> 대학 재정지원사업 서식을 불러와 **문서를 자동 생성·검증·수정·변환·저장**하는 시스템.
> 읽는 순서: **1장(무엇을 하는가) → 2장(메뉴 Depth) → 3장(처리 흐름) → 4장(기능 상세)**.
> 앞 장일수록 개략, 뒤 장일수록 상세하다.

---

## 1. 한눈에 보기

사용자는 서식을 고르고 값을 입력한다. 시스템은 서식 규칙대로 검증하고, 본문 초안을 만들고, 오류를 짚어 수정하게 한 뒤, HWP/PDF로 내려받게 한다.

```
템플릿 로딩 → 문서 생성 → 문서 검증 → 오류 탐지 → 문서 수정 → 문서 변환(HWP, PDF) → 저장 및 다운로드
   F1          F2          F3          F4          F5            F6                   F7
```

### 1.1 역할 정의

| 역할 | 하는 일 | 접근 |
|---|---|---|
| 사용자 (작성자) | 서식 선택 → 입력 → 검증 → 수정 → 변환 → 다운로드. **문서 생성은 사용자가 한다** | 서식 선택, 문서 작성, 내 문서함 |
| 관리자 | 사용자가 쓸 **서식·입력폼·검증 규칙을 준비**하고 계정·시스템을 운영 | 사용자 화면 전체 + 관리자 페이지 |

- 서식 등록·입력폼·규칙 변경은 관리자만, 문서 작성은 사용자가 한다. 관리자도 점검용으로 사용자 흐름을 쓸 수 있다.
- **로그인**으로 두 역할을 구분하고, 문서는 **계정별로 따로 보관**한다(개인화). 계정은 관리자가 직접 등록한다(가입 신청·승인 없음).
- 역할별 권한 매트릭스는 `Capstone.xlsx`의 "역할 정의" 시트에 있다.

---

## 2. 메뉴 구조 (Depth)

Depth는 3단계로 고정하지 않는다. 기능이 더 나뉘면 5단계까지 내려간다.
**이 트리는 `Capstone.xlsx`(기능명세) 본 시트에서 생성한 것이다.** 괄호 안은 기능 코드이며, 수정은 xlsx에서 한다.
대괄호는 사용 주체다(공통 / 사용자 / 관리자).

### 2.2 메뉴 간 연결

| 출발 | 도착 | 의미 |
|---|---|---|
| 관리자 > 서식 관리 | 서식선택 | 관리자가 공개한 서식만 사용자에게 보인다 |
| 관리자 > 서식 관리 > 스키마 자동 추출 | 관리자 > 입력폼 관리 | 스키마(필드·표·슬롯·반복영역)가 입력폼의 초안이 된다 |
| 관리자 > 입력폼 관리 | 정보입력 > 입력폼 | 관리자가 구성한 항목이 사용자 입력 화면이 된다 |
| 관리자 > 검증 규칙 관리 | 실시간 점검 / 입력 완료 검증 / 오류 탐지 | 같은 규칙을 실시간·완료 시점·결과 화면이 공유한다 |
| 오류 탐지 > 오류 목록 | 문서 수정 | 오류 클릭 시 해당 입력 칸으로 이동 |
| 저장·다운로드 | 내 문서함 > 완료 문서 | 저장하면 로그인한 본인의 문서함에 쌓인다 |
| 로그인 | 역할별 메뉴 | 사용자는 사용자 화면만, 관리자는 관리자 페이지까지 노출 |

## 3. 처리 흐름 (기능 단위)

메뉴가 아니라 **한 문서가 거치는 단계**로 쪼갠 것이다. 각 단계는 4장에서 상세히 설명한다.

| 단계 | 기능 | 한 줄 설명 | 담당 | 구현 |
|---|---|---|---|---|
| F1 | 템플릿 로딩 | 서식(HWPX)과 스키마를 불러온다 | 코드 | ✅ |
| F2 | 문서 생성 | 입력값 주입 + 본문 초안 생성 | 코드 + LLM | 🔶 주입 ✅ / 초안 ⬜ |
| F3 | 문서 검증 | 입력 중 점검 + 완료 시점 전체 검증 | 규칙 코드 | 🔶 |
| F4 | 오류 탐지 | 위반을 위치·사유와 함께 목록화, 정성 판정 | 규칙 + LLM | 🔶 규칙 ✅ / 정성 ⬜ |
| F5 | 문서 수정 | 오류 칸 수정 → 재검증 반복 | UI | ⬜ |
| F6 | 문서 변환 | HWPX → HWP / PDF | 한컴 COM | ✅ |
| F7 | 저장·다운로드 | 산출물 보관, 이력, 내려받기 | 서버 | ⬜ |

## 4. 기능 상세

### F1. 템플릿 로딩

| 항목 | 내용 |
|---|---|
| 목적 | 선택한 서식의 구조와 채울 지점을 메모리에 올린다 |
| 입력 | 서식 ID |
| 처리 | `templates/…/*.hwpx` 열기 → `schemas/…/*.json` 로드 |
| 출력 | 필드(누름틀), 표, 슬롯, 반복영역 |
| 연결 | 관리자 > 서식 관리가 공급, 정보입력으로 전달 |
| 예외 | 서식 파일 없음 / 스키마 불일치 → 사용자에게 "서식 준비 중" 안내, 관리자 알림 |
| 코드 | `docflow/hwpx/document.py`, `docflow/schema/form.py` |

### F2. 문서 생성

F2는 단순 "채우기"가 아니라 **두 갈래**다.

**F2-a. 값 주입 (결정적)**

| 항목 | 내용 |
|---|---|
| 처리 | 누름틀은 이름 키로, 표 셀은 좌표로, 반복영역은 행 단위로 주입 |
| 특징 | 같은 입력이면 항상 같은 결과. 결재란(`apbN_*`)은 사용자 입력 대상이 아니다 |
| 코드 | `HwpxDocument.fill()` |

**F2-b. 본문 초안 생성 (LLM)**

| 항목 | 내용 |
|---|---|
| 대상 | 기안문 `content_body`, 계획서의 목적·추진 배경 등 서술형 칸 |
| 입력 | 이미 입력된 값(사업명, 기간, 금액, 대상 인원) + 문체 지침 |
| 처리 | 로컬 LLM이 공문 문체로 초안 생성. 숫자·날짜는 입력값을 **그대로 인용**(재계산 금지) |
| 출력 | 초안 텍스트 + 인용한 입력 항목 목록 |
| 사용자 행동 | 채택 / 직접 수정 / 재생성 |
| 보안 | 학생 명단·계좌번호는 LLM 프롬프트에서 제외 (로컬 실행이라도 최소 전달) |
| 상태 | ⬜ (로드맵 6단계) |

### F3. 문서 검증

검증은 **두 시점**에 같은 규칙으로 돈다. 시점별로 보이는 결과가 다르다.

| 구분 | 입력 중 (실시간) | 입력 완료 시 (제출) |
|---|---|---|
| 메뉴 | 정보입력 > 실시간 점검 | 입력 완료 검증 |
| 시점 | 칸에서 포커스가 벗어날 때 | "검증" 버튼 |
| 범위 | 그 칸 하나 (+ 연관 칸) | 문서 전체 |
| 하는 일 | 형식 점검, **중복 체크**, 합계 즉시 계산 | 필수 누락, 합계 일치, 날짜 순서, 문서 간 일치 |
| 표시 | 칸 옆 경고 아이콘 (입력을 막지 않음) | 오류 목록 화면(오류 탐지) |
| 근거 | 같은 규칙을 칸 단위로 호출 | `validate(schema, values, fields)` |

**실시간 중복 체크 대상** (확정 필요 → 8장): 같은 문서 안 반복 행의 학번·성명 중복, 같은 사업·기간의 동일 문서번호.

**규칙 목록 (현재 구현)**

| 규칙 | 코드 | 검사 | 적용 서식 |
|---|---|---|---:|
| 필수 누락 | `REQUIRED_EMPTY` | 자리표시자가 있던 칸이 비었는가 | 177/183 |
| 금액 합계 | `AMOUNT_TOTAL_MISMATCH` | 합계 셀 = 직전 합계 이후 행의 합 | 78/183 |
| 날짜 | `DATE_INVALID`, `DATE_ORDER` | 형식, 연속된 날짜의 선후 | 95/183 |
| 문서 간 대조 | (미정) | 계획서 금액 = 정산서 금액 등 | ⬜ |

제외 규칙(오탐 방지)은 README 8장 참고.

### F4. 오류 탐지

**F3이 "검사"라면 F4는 "결과를 쓸 수 있게 만드는 것"이다.** 검증만 끝나고 끝나면 사용자가 할 일이 안 보인다는 지적을 여기서 해결한다.

| 항목 | 내용 |
|---|---|
| 입력 | F3의 `Issue` 목록 |
| 처리 | 심각도 분류(오류 / 경고), 위치 매핑(표 번호·셀 좌표·누름틀 이름), 사유와 **고치는 방법** 문구 부여 |
| 출력 | 오류 목록 화면: 항목명, 현재값, 사유, 권장 조치, 이동 버튼 |
| 정성 판정 | 규정 해석이 필요한 항목(예: 비목 적정성)은 LLM이 체크리스트로 판정, 근거 문장 제시 |
| 결과 분기 | 오류 0건 → F6 활성화 / 오류 있음 → F5로 / 경고만 → 확인 후 진행 가능 |
| 상태 | 규칙 기반 ✅, 위치 매핑·정성 판정 ⬜ |

### F5. 문서 수정

| 항목 | 내용 |
|---|---|
| 진입 | 오류 목록에서 항목 클릭 → 해당 입력 칸으로 이동 |
| 처리 | 칸 수정 → 해당 규칙만 즉시 재검증 → 오류 목록 갱신 |
| 완료 조건 | 전체 재검증 통과 (또는 경고만 남고 사용자가 확인) |
| 초안 수정 | F2-b 초안은 자유 편집, 편집 후에도 입력값과 숫자가 어긋나면 경고 |
| 상태 | ⬜ (로드맵 7단계 UI) |

### F6. 문서 변환 (HWP, PDF)

| 항목 | 내용 |
|---|---|
| 입력 | 검증 통과한 HWPX |
| 처리 | 한컴 COM으로 `.hwp`, `.pdf` 저장 |
| 제약 | Windows + 한컴오피스 필요 → 변환 워커로 격리 (`docflow/adapters/hancom.py`) |
| 예외 | 변환 실패/워커 중단 → 재시도 1회 후 오류 안내, HWPX는 보존. 좀비 프로세스는 `Hancom.close()`가 정리 |
| 상태 | ✅ |

### F7. 저장·다운로드

| 항목 | 내용 |
|---|---|
| 처리 | 산출물(HWPX/HWP/PDF)과 입력값·검증 결과를 문서 이력으로 저장 |
| 다운로드 | 형식 선택(HWP / PDF), 파일명 규칙 `서식번호_문서명_작성일` |
| 연결 | 내 문서함 > 완료 문서에서 재다운로드·재수정(정보입력으로) |
| 상태 | ⬜ (로드맵 7단계) |

## 8. 확정이 필요한 사항

1. 실시간 중복 체크의 대상 범위 (4장 F3).
2. 경고만 남은 문서를 변환해도 되는지, 관리자 승인이 필요한지.
3. 관리자 페이지의 입력폼 관리를 직접 편집으로 할지, 스키마 자동 추출 결과를 승인만 하는 방식으로 할지. 서식이 183개라 후자를 권장한다.
4. 문서 간 대조 규칙의 대상 서식 쌍.
5. 로그인은 기획에 없던 기능이라 팀 합의가 필요하다. 제안하는 범위는 로그인·계정 관리·역할 2종이며, 가입 신청·승인은 제외한다. 제외하기로 하면 "내 문서함"과 "전체 문서 조회"도 함께 뺀다.
