# DocFlow 기능명세서

> 대학 재정지원사업 서식을 불러와 **문서를 자동 생성·검증·수정·변환·저장**하는 시스템.
> 읽는 순서: **1장(무엇을 하는가) → 2장(메뉴 Depth) → 3장(처리 흐름) → 4장(기능 상세)**.
> 앞 장일수록 개략, 뒤 장일수록 상세하다.
> **모든 기능은 미개발 상태를 전제로 정의한다.** 구현 상태는 이 문서에 적지 않으며, 진행 현황은 `README.md` 6장 로드맵과 `docs/index.html`에 있다.
> 기능 목록의 원본은 팀 공유 파일 `Capstone.xlsx`(저장소 미포함)이고, 2.1 트리는 그 파일에서 만든 것이다.

## 1. 한눈에 보기

사용자는 서식을 고르고 **작성할 내용을 문장으로 적는다(프롬프트)**. 로컬 LLM이 그 내용을 서식의 칸에 나눠 채우고, 학생 명단·계좌는 학생에게 받은 입금계좌 확인서(HWP)를 올려 채운다. 사용자는 채워진 칸을 확인·수정하고, 시스템은 서식 규칙대로 검증하고, 본문 초안을 만들고, 오류를 짚어 수정하게 한 뒤, HWP/PDF로 내려받게 한다.

칸을 하나씩 직접 채우는 입력 화면은 **LLM 결과를 확인·수정하는 화면이자, LLM을 쓸 수 없을 때의 대체 경로**다.

```
템플릿 로딩 → 문서 생성 → 문서 검증 → 오류 탐지 → 문서 수정 → 문서 변환(HWP, PDF) → 저장 및 다운로드
   F1          F2          F3          F4          F5            F6                   F7
```

### 1.1 역할 정의

| 역할 | 하는 일 | 접근 |
|---|---|---|
| 사용자 (작성자) | 서식 선택 → 입력 → 검증 → 수정 → 변환 → 다운로드. **문서 생성은 사용자가 한다** | 서식 선택, 문서 작성, 내 문서함 |
| 관리자 | 사용자가 쓸 **서식·입력폼·검증 규칙을 준비**하고 계정·시스템을 운영 | 사용자 화면 전체 + 관리자 페이지 |

- 서식 등록·입력폼·규칙 변경은 관리자만, 문서 작성은 사용자가 한다. 관리자도 점검용으로 사용자 흐름을 쓸 수 있다.
- **로그인**으로 두 역할을 구분하고, 문서는 **계정별로 따로 보관**한다(개인화). 계정은 **관리자가 IAM 방식으로 발급**한다(아이디·초기 비밀번호 발급 → 사용자가 그 아이디로 이용). 가입 신청·승인과 비밀번호 찾기는 없고, 분실 시 관리자가 초기화한다. 첫 로그인 때 비밀번호 변경을 강제한다.
- **로그인 정책**
  - 비밀번호: 대문자·소문자·숫자·특수문자를 모두 포함해 8자 이상.
  - 실패: 3회 연속 실패하면 계정을 잠그고, **관리자만 해제**한다(자동 해제 없음).
  - 루트 관리자: AWS IAM의 루트 계정처럼 1개만 두고, 서버 설치 시 CLI로 만든다. 관리자 계정의 발급·잠금 해제는 루트만 한다. 루트가 잠기면 서버 CLI로만 해제한다.
  - 세션: 30분 유지. 우측 상단에 남은 시간과 연장 버튼을 띄우고, 누르면 다시 30분. 입력 중 만료되면 경고(alert) 후 5분 자동 연장(1회).
  - 동시 로그인: 같은 계정이 새로 로그인하면 기존 로그인은 로그아웃된다.
- **사업별 접근 제한은 없다.** 사용자는 앵커·AID·혁신 전 사업의 서식을 쓸 수 있다.
- **관리자의 문서 열람**: 관리자는 남의 문서를 목록(이름·작성자·서식·상태·검증 오류 수)으로만 본다. 입력값과
  파일은 **사유를 적어야** 열람·내려받기가 되고, 사유와 함께 감사 로그에 남는다. 열람 화면에서 주민등록번호는
  뒷자리를 가린다.
- **관리자의 변경 기록**: 계정·서식·입력폼·카테고리·검증 규칙·문서 간 대조 규칙·시스템 설정을 바꾸면 감사 로그에 남는다.
  비밀번호는 적지 않는다.
- 역할별 권한 매트릭스는 `Capstone.xlsx`의 "역할 정의" 시트에 있다.

### 1.2 용어

이 문서에 자주 나오는 말이다. 전체 목록은 `Capstone.xlsx`의 "용어집" 시트에 있다.

| 용어 | 뜻 |
|---|---|
| 누름틀 | 한글 문서에 미리 심어 둔 이름 붙은 입력 칸 (문서번호, 시행일자 등) |
| 표 칸 (슬롯) | 누름틀이 아닌, 표 안에서 채워야 할 칸. 자리표시자가 적힌 칸(필수)과 항목명 옆 빈 칸(선택) |
| 자리표시자 | 서식 칸에 미리 적힌 예시 형식(`2000.00.00`, `0,000,000원`). 채울 칸과 입력 유형을 알아내는 근거 |
| 반복영역 / 예시 행 | 명단·내역처럼 반복되는 표 부분 / 그 맨 위에 샘플로 적힌 행(홍길동 등) |
| 서식 구조 정보 (스키마) | 서식에서 자동으로 뽑은 채울 칸 목록. 입력 화면과 검증의 기준 |
| 결재란 | 결재선이 채우는 칸(`apbN_*`). 작성자 입력 대상이 아니다 |
| 한컴 COM / 변환 서버(워커) | 한글 프로그램을 코드로 조작하는 방식 / 그 변환만 따로 맡는 서버 |
| 오탐 | 문제없는 것을 오류로 잘못 잡는 것 |
| 정성 판정 | 규정 해석이 필요한 항목을 LLM이 체크리스트로 판단하는 것 |
| 프롬프트 입력 (자연어 일괄 입력) | 작성할 내용을 문장으로 적으면 LLM이 서식의 칸에 나눠 채우는 것. 결과는 사용자가 확인한 뒤 반영한다 |
| 묶음 파일 | 서식 여러 개가 든 템플릿 파일(예: `[AID 서식 1-01~10호] 일반기안문(샘플 10종)`). 서식 번호마다 따로 목록에 오른다 |

## 2. 메뉴 구조 (Depth)

Depth는 3단계로 고정하지 않는다. 기능이 더 나뉘면 5단계까지 내려간다.
**이 트리는 `Capstone.xlsx`의 "기능명세" 시트에서 생성한 것이다.** 괄호 안은 기능 코드이며, 수정은 xlsx에서 한다.
대괄호는 사용 주체다(공통 / 사용자 / 관리자).

## 4. 기능 상세

### F1. 템플릿 로딩

| 항목 | 내용 |
|---|---|
| 목적 | 선택한 서식의 구조와 채울 지점을 메모리에 올린다 |
| 입력 | 서식 ID |
| 처리 | `templates/…/*.hwpx` 열기 → `schemas/…/*.json` 로드 |
| 출력 | 누름틀, 표, 표 칸(슬롯), 반복영역 |
| 연결 | 관리자 > 서식 관리가 공급, 정보입력으로 전달 |
| 예외 | 서식 파일 없음 / 스키마 불일치 → 사용자에게 "서식 준비 중" 안내, 실패는 감사 로그에 남겨 관리자 페이지에 표시 |
| 묶음 파일 | 서식 머리의 번호 표시(`[ AID 서식 1-02호 ]`)를 경계로 나눠 **서식 번호마다 따로 목록에 올린다**. 템플릿은 같이 쓰고, 문서를 만들 때 고른 서식의 쪽만 남긴다. 번호가 파일 이름의 번호 밖이면 나누지 않는다(잘못 적힌 표시). 묶음 이름에 갈래가 있으면 서식 이름 뒤에 붙인다(`(선대응)`). 같은 서식의 판이 여러 개면(`7-01-1호`, `7-01-2호`) 한 서식 안에서 고른다 |

### F2. 문서 생성

F2는 단순 "채우기"가 아니라 **네 갈래**다. a는 값을 문서에 넣고, b~d는 넣을 값을 만든다.

**F2-a. 값 주입 (결정적)**

| 항목 | 내용 |
|---|---|
| 처리 | 누름틀은 이름 키로, 표 셀은 좌표로, 반복영역은 행 단위로 주입 |
| 반복영역 | 헤더 바로 아래 예시 행(홍길동 등)은 첫 행으로 보고 첫 번째 입력 행 값으로 덮어쓴다. 입력하지 않은 행과 예시 항목 행은 비운다(미리 적힌 연번·금액 포함 — 남기면 수식 합계에 더해진다) |
| 특징 | 같은 입력이면 항상 같은 결과. 결재란(`apbN_*`)은 사용자 입력 대상이 아니다 |

**F2-b. 본문 초안 생성 (LLM)**

| 항목 | 내용 |
|---|---|
| 대상 | 기안문 `content_body`, 계획서의 목적·추진 배경 등 서술형 칸 |
| 입력 | 이미 입력된 값(사업명, 기간, 금액, 대상 인원) + 문체 지침 |
| 처리 | 로컬 LLM이 공문 문체로 초안 생성. 숫자·날짜는 입력값을 **그대로 인용**(재계산 금지) |
| 출력 | 초안 텍스트 + 인용한 입력 항목 목록 |
| 사용자 행동 | 채택 / 직접 수정 / 재생성 |
| 보안 | 학생 명단·계좌번호·주민등록번호는 LLM에 넘기지 않는다 (6장) |

**F2-c. 자연어 일괄 입력 (LLM)**

| 항목 | 내용 |
|---|---|
| 입력 | 사용자가 적은 프롬프트 (예: "10월 12일 산학협력처 취업역량강화 운영 계획, 예산 150만 원…") |
| 처리 | 서식의 채울 칸 목록(누름틀 한글 이름, 표 칸, 입력 유형)을 LLM에 주고, 칸 이름을 키로 하는 JSON 으로만 답하게 한다(스키마 제약 출력). 고른 서식의 칸만 넘긴다 |
| 출력 | 칸별 값. 바로 저장하지 않고 입력 화면에 채워 보여 준다 |
| 인용 검사 | 채운 금액·날짜가 프롬프트에 실제로 있는지 대조하고, 없으면 경고 (F2-b 와 같은 방식) |
| 검증 | 채운 뒤에는 F3 규칙이 그대로 돈다. LLM은 값을 제안할 뿐 검증 결과를 바꾸지 않는다 |
| 보안 | 명단·계좌·주민등록번호 칸은 LLM 대상에서 뺀다 (F2-d 로 채운다) |
| 예외 | LLM을 쓸 수 없으면 입력 화면에서 직접 채운다 |

**F2-d. 명단 가져오기 (결정적)**

| 항목 | 내용 |
|---|---|
| 입력 | 학생에게 받은 입금계좌 확인서 HWP·HWPX 여러 개 (우리 서식 4-01호 등) |
| 처리 | HWP → HWPX 변환(F6 과 같은 한컴 변환) → 머리줄 이름으로 **열의 뜻**(성명·예금주, 은행, 계좌번호, 주민등록번호, 학번, 학과, 학년, 금액, 주소, 연락처)을 찾아 명단 행을 읽음 → 작성 중인 서식의 명단 열도 이름으로 뜻을 찾아 맞춰 넣음. 한 줄·두 줄 머리(`입금계좌` 아래 `은행명 / 계좌번호`)를 모두 읽고, 학생이 행을 더하거나 지워도 된다 |
| 빼는 줄 | 지우지 않은 예시 줄(`000`, `홍길동`), 빈 줄, 미리 적힌 금액만 있는 줄, 합계 줄. 성명·계좌번호가 같은 사람은 한 번만 넣는다 |
| 출력 | 명단 행. 저장하지 않고 입력 화면에서 미리 보여 주며(찾은 사람 수, 읽지 못한 파일과 이유, 채울 열·비워 둘 열), 사용자가 "뒤에 더하기" 또는 "바꾸기"로 반영한다. 받는 명단에 없는 열의 값은 옮기지 않는다 |
| 보안 | LLM 을 거치지 않는다. 올린 파일은 읽고 바로 지운다 |
| 종이로 받은 경우 | 입력 화면에 직접 입력한다. 손글씨 OCR 은 하지 않는다(계좌번호·주민등록번호는 한 자리만 틀려도 송금 사고가 난다). 대신 형식 점검을 강화한다(F3) |

### F3. 문서 검증

검증은 **두 시점**에 같은 규칙으로 돈다. 시점별로 보이는 결과가 다르다.

| 구분 | 입력 중 (실시간) | 입력 완료 시 (제출) |
|---|---|---|
| 메뉴 | 정보입력 > 실시간 점검 | 입력 완료 검증 |
| 시점 | 다른 칸으로 넘어갈 때(포커스 이탈) | "검증" 버튼 |
| 범위 | 그 칸 하나 (+ 연관 칸) | 문서 전체 |
| 하는 일 | 형식 점검, **중복 체크**, 합계 즉시 계산 | 필수 누락, 합계 일치, 날짜 순서, 문서 간 일치 |
| 표시 | 칸 옆 경고 아이콘 (입력을 막지 않음) | 오류 목록 화면(오류 탐지) |
| 근거 | 같은 규칙을 칸 단위로 호출 | `validate(schema, values, fields)` |

**실시간 중복 체크 대상**: 같은 문서 안 반복 행의 **학번** 중복(성명은 동명이인이 있어 보지 않는다). 같은 사업·기간의 동일 문서번호는 확정 필요(8장).

**규칙 목록**

| 규칙 | 코드 | 검사 | 적용 서식 |
|---|---|---|---:|
| 필수 누락 | `REQUIRED_EMPTY` | 자리표시자가 있던 칸·필수 누름틀이 비었는가 | 183/183 |
| 금액 합계 | `AMOUNT_TOTAL_MISMATCH` | 작성자가 적는 합계 칸 = 항목의 합. 반복영역 바로 아래 합계 행은 입력한 행들의 합, 그 밖은 같은 열에서 직전 합계 다음 칸부터의 합 (수식 합계는 다시 계산하므로 제외) | 49/183 |
| 날짜 | `DATE_INVALID`, `DATE_ORDER` | 형식, 연속된 날짜의 선후 | 107/183 |
| 금액 형식 (경고) | `AMOUNT_INVALID` | 금액 칸 값이 금액으로 읽히는가 (`5,000` `5,000원` `₩ 5,000` 허용, `해당 없음`·`-` 은 통과) | 102/183 |
| 반복 행 중복 (경고) | `ROW_DUPLICATE` | 명단 안에 같은 학번이 두 번 나오는가. 두 번째 행부터 경고 | 54/183 |
| 계좌번호 형식 (경고) | `ACCOUNT_INVALID` | 숫자·하이픈만, 숫자 9~16자리. 은행별 자릿수는 보지 않는다(은행마다 계좌 종류가 여러 개라 오탐이 난다) | 23/183 |
| 주민등록번호 형식 (경고) | `RRN_INVALID` | `생년월일 6자리-성별 자리(1~8)+6자리`, 생년월일이 달력에 있는 날. 가린 뒷자리(`1******`) 허용. 검증 숫자는 보지 않는다(2020년 10월 이후 번호는 따르지 않는다). 외국인등록번호·국적도 받는 칸은 제외 | 12/183 |
| 예금주·성명 (경고) | `HOLDER_MISMATCH` | 명단에 성명 열과 예금주 열이 따로 있을 때 두 값이 같은가 (`성명 (예금주)` 한 열이면 보지 않는다) | 0/183 |
| 문서 간 대조 (경고) | `CROSS_AMOUNT_MISMATCH` | 관리자가 정한 서식 쌍에서, 사용자가 이어 둔 두 문서의 금액(고른 항목들의 합)이 같은가 / 대상이 기준을 넘지 않는가. 양쪽 문서에서 보인다. 수식 합계 칸은 입력이 아니라 항목 칸들을 더한다 | 규칙별 |

적용 서식 수는 2026-10 측정값이고 템플릿 **파일** 183개 기준이다(로컬 회귀 테스트가 고정한다). 경고는 입력을 막지 않는다.
관리자는 규칙을 전체로 끄거나 특정 서식에서만 끌 수 있고, 실시간 점검·완료 검증·문서 만들기에 모두 적용된다(11.4).
계좌번호·주민등록번호 칸은 칸 이름(`계좌번호`, `주민등록번호` …)으로 알아본다.

제외 규칙(오탐 방지)은 README 8장 참고.

### F4. 오류 탐지

**F3이 "검사"라면 F4는 "결과를 쓸 수 있게 만드는 것"이다.** 검증만 끝나고 끝나면 사용자가 할 일이 안 보인다는 지적을 여기서 해결한다.

| 항목 | 내용 |
|---|---|
| 입력 | F3의 `Issue` 목록 |
| 처리 | 심각도 분류(오류 / 경고), 오류 위치 표시(표 번호·셀 좌표·누름틀 이름), 사유와 **고치는 방법** 문구 부여 |
| 출력 | 오류 목록 화면: 항목명, 현재값, 사유, 권장 조치, 이동 버튼 |
| 정성 판정 | 규정 해석이 필요한 항목(예: 비목 적정성)은 LLM이 체크리스트로 판정, 근거 문장 제시 |
| 결과 분기 | 오류 0건 → F6 활성화 / 오류 있음 → F5로 / 경고만 → 확인 후 진행 가능 |

### F5. 문서 수정

| 항목 | 내용 |
|---|---|
| 진입 | 오류 목록에서 항목 클릭 → 해당 입력 칸으로 이동 |
| 처리 | 칸 수정 → 해당 규칙만 즉시 재검증 → 오류 목록 갱신 |
| 완료 조건 | 전체 재검증 통과 (또는 경고만 남고 사용자가 확인) |
| 초안 수정 | F2-b 초안은 자유 편집, 편집 후에도 입력값과 숫자가 어긋나면 경고 |

### F6. 문서 변환 (HWP, PDF)

| 항목 | 내용 |
|---|---|
| 입력 | 검증 통과한 HWPX |
| 처리 | 한컴 COM으로 `.hwp`, `.pdf` 저장 |
| 제약 | Windows + 한컴오피스 필요 → 변환 워커로 격리 (`docflow/adapters/hancom.py`) |
| 예외 | 변환 실패/워커 중단 → 재시도 1회 후 오류 안내, HWPX는 보존. 남은 한글 프로세스는 `Hancom.close()`가 정리 |

### F7. 저장·다운로드

| 항목 | 내용 |
|---|---|
| 처리 | 산출물(HWPX/HWP/PDF)과 입력값·검증 결과를 문서 이력으로 저장 |
| 다운로드 | 형식 선택(HWP / PDF), 파일명 규칙 `서식번호_문서명_작성일` |
| 연결 | 내 문서함 > 완료 문서에서 재다운로드·재수정(정보입력으로) |

## 6. 비기능 요구

| 항목 | 기준 |
|---|---|
| 재현성 | 규칙 검증은 같은 입력에 같은 결과 (결재 문서) |
| 오탐 | 경고가 잦으면 아무도 안 보므로 **오탐 억제를 재현율보다 우선** |
| 개인정보 | LLM은 로컬 실행. **학생 명단·계좌번호·주민등록번호는 LLM에 넘기지 않는다** — 학생에게 받은 입금계좌 확인서(HWP)를 올리거나 직접 입력해서 채운다. 학생 정보는 개인정보 수집·활용 동의서를 받고 모은 것을 전제로 한다 |
| 암호화 | 주민등록번호가 들 수 있는 문서 **입력값·이력의 입력값 사본·만든 파일(HWPX·HWP·PDF)** 은 AES-256-GCM 으로 암호화해 저장하고, 본인이 열거나 내려받을 때만 푼다. 키는 DB 와 따로 둔다(환경변수 또는 키 파일, 클라우드에서는 KMS). 키를 잃으면 복구할 수 없으므로 따로 백업한다 |
| 감사 | 규칙이 코드로 남고, 문서 이력에 어떤 규칙으로 통과했는지 기록 |
| 이전성 | COM 의존은 어댑터 한 곳에 격리 (Phase 2 AWS 이전) |
