# DocFlow — 서식 기반 문서 자동 생성 및 검증 시스템

연성대학교 재정지원사업 서식을 기반으로 **문서를 자동 생성하고, 서식·규정 준수 여부를 검증**하는 시스템입니다.
장기적으로는 결재 라인 자동화(반려/통과 판정)까지 확장합니다.

> 현재 상태: **Phase 1 초기 구현 중**

---

## 1. 대상 서식 현황

`forms/` 아래 학교에서 받은 원본 서식이 있습니다. (저작물이므로 `.gitignore` 처리 — 커밋되지 않음)

| 사업 | 경로 | 비고 |
|---|---|---|
| 2026 앵커(신산업) | `forms/ysu_forms/[2026 앵커(신산업)] 서식모음` | **1차 개발 대상** (가장 많이 사용) |
| 2026 혁신 | `forms/ysu_forms/2026_혁신` | 구버전(`0_2025학년도 이전`) 포함 |
| 2026 AID | `forms/ysu_forms/2026_AID` | 아직 zip 상태, 자체운영지침 PDF 포함 |

전체 158개 파일 = **HWP 146 / XLSX 5 / PDF 6 / ZIP 1**. HWP는 전부 **HWP 5.0(OLE/CFB) 포맷**입니다.

서식 번호 체계는 사업별로 동일합니다:

```
1_기안문  2_계획서및보고서  3_정산서  4_인건비  5_학생지원비
6_국내외여비  7_회의비  8_물품구입비  9_도서구입비
```

## 2. 서식 구조 분석 결과 (설계 근거)

1차 대상인 `(서식 1-01~04호) 일반기안문(샘플).hwp` 을 해부한 결과:

- **누름틀(필드) 144개**가 심어져 있고, **필드마다 이름이 있음**
  (`docnumber`, `enforcedate`, `apb1_type`/`apb1_date`/`apb1_sign` … `apb8_*`,
   `zipcode`, `address`, `telephone`, `fax`, `email`, `publication`, `seal`, `content_body` — 고유 36종)
- `apbN_*` 는 **결재란(approval box)** 이며, 결재선 자동화의 직접적인 주입 지점입니다.
- **본문은 `content_body` 단일 필드**로만 잡혀 있음 → 본문의 세부 항목(관련·일시·장소·예산·재원·붙임)은
  개별 필드가 아니라 일반 텍스트. 따라서 **"필드 채우기 + 본문 문안 생성"** 하이브리드가 필요합니다.

이 구조는 HWPX(zip+XML)로 변환하면 아래처럼 그대로 드러납니다:

```xml
<hp:ctrl><hp:fieldBegin id="1298154009" type="CLICK_HERE" name="docnumber" .../></hp:ctrl>
<hp:t>○○○○처-000000</hp:t>
<hp:ctrl><hp:fieldEnd beginIDRef="1298154009" .../></hp:ctrl>
```

`fieldBegin.id` ↔ `fieldEnd.beginIDRef` 로 짝을 짓고, 그 사이 `<hp:t>` 가 값입니다.

## 3. 아키텍처 결정

### 3.1 HWP 처리 — 하이브리드
- **주 경로(순수 파이썬)**: 템플릿을 HWPX로 1회 변환해 두고, 값 주입은 zip+XML 조작으로 처리.
  한컴오피스 없이 동작하고, 테스트·diff가 가능하며, 서버 이전이 쉽습니다.
- **보조 경로(로컬 전용)**: 최종 `.hwp` / `.pdf` 산출과 원본 `.hwp → .hwpx` 변환은 한컴 COM 사용.

> **왜 이렇게 나눴나**: 한컴 COM은 Windows + 한컴오피스가 깔린 기기에서만 동작해 AWS로 못 올라갑니다.
> COM 의존을 `docflow/adapters/hancom.py` 한 곳에 가둬 두면, Phase 2에서 이 모듈만 떼거나
> 별도 Windows 워커로 분리하면 됩니다. 코어(`docflow/hwpx`)는 COM을 import 하지 않습니다.

### 3.2 생성·검증 — LLM 하이브리드
| 구분 | 담당 | 이유 |
|---|---|---|
| 필수항목 누락, 금액 합계, 날짜 형식·순서, 문서 간 금액 일치 | **규칙 코드** | 재현성·속도·비용. 결재 문서라 같은 입력에 다른 결과가 나오면 안 됨 |
| 본문 문안 생성, 규정 해석이 필요한 정성 검증 | **LLM** | 지침 해석과 자연스러운 공문 문체가 필요한 영역 |

### 3.3 LLM — 로컬 실행
학생 명단·계좌번호 등 개인정보가 외부로 나가지 않도록 **로컬 LLM**을 사용합니다.
(현 개발 장비: RTX 3060 12GB → 7B~14B 양자화 모델 범위)

### 3.4 검증 기준 주입 — 서식별 체크리스트 사전 추출
지침·서식을 한 번 분석해 **서식별 검증 규칙 JSON**을 만들어 두고, 런타임에는 그 규칙만 프롬프트에 넣습니다.
매번 지침 PDF를 RAG로 검색하는 방식보다 저렴·빠르고, 규칙이 파일로 남아 **감사(audit)가 가능**합니다.

### 3.5 결재 자동화 범위
- **지금**: 문서 생성 + 서식 검증
- **나중**: 결재 라인 자동 진행, 참조/첨부/서식 부적합 판단 → 반려/통과 구분

## 4. 디렉터리 구조

```
DocFlow/
├─ docflow/
│  ├─ hwpx/document.py     # HWPX 읽기·쓰기 (순수 파이썬, 플랫폼 무관)
│  └─ adapters/hancom.py   # 한컴 COM 어댑터 (로컬 전용, 격리 대상)
├─ tools/
│  └─ convert_templates.py # forms/*.hwp → templates/*.hwpx 일괄 변환
├─ forms/                  # 원본 서식 (gitignore)
├─ templates/              # 변환된 HWPX 템플릿 (gitignore)
└─ requirements.txt
```

## 6. 개발 환경

- Windows 11 / Python 3.12 / **한컴오피스 2022 (한글 12.0)** — COM ProgID `HWPFrame.HwpObject`
- 참고: 코어 코드는 한컴오피스 없이도 동작합니다. COM은 템플릿 변환과 최종 산출에만 필요합니다.

```powershell
.\.venv\Scripts\python.exe -u tools\convert_templates.py "forms/ysu_forms/[2026 앵커(신산업)] 서식모음"
```

### 알려진 함정 — 좀비 한글 프로세스
COM으로 띄운 한글이 `Quit()` 후에도 남는 경우가 있고, 남은 인스턴스에 다음 `Dispatch` 가 붙으면
`Open()` 에서 **무한 대기**합니다 (실제로 배치 변환이 여기서 멈췄습니다).
`Hancom.close()` 가 자신이 띄운 PID를 추적해 강제 정리하므로 보통은 신경 쓸 필요 없지만,
비정상 종료 후 변환이 멈추면 확인하세요:

```powershell
Get-Process Hwp -ErrorAction SilentlyContinue | Select-Object Id, StartTime, MainWindowTitle
# 창 제목이 비어 있으면 자동화가 띄운 고아 프로세스 -> 종료해도 안전
```
