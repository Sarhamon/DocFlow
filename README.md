# DocFlow — 서식 기반 문서 자동 생성 및 검증 시스템

대학 재정지원사업 서식을 기반으로 **문서를 자동 생성하고, 서식·규정 준수 여부를 검증**하는 시스템입니다.
장기적으로는 결재 라인 자동화(반려/통과 판정)까지 확장합니다.

캡스톤 디자인(졸업작품) 프로젝트이며, 현재 **M0~M8 완료**(문서 엔진, 서식 3종 관통, 웹 API, 로그인, 사용자 화면)이고 다음은 LLM·입력 자동화(M10)입니다.
진행 현황은 [`docs/index.html`](docs/index.html), 개발 계획은 [`docs/dev-roadmap.md`](docs/dev-roadmap.md)에 있습니다.
무엇을 만드는지는 [`docs/functional-spec.md`](docs/functional-spec.md)(기능명세서)에 정리했습니다.
기능 목록의 원본은 팀 공유 파일 `Capstone.xlsx`이며(저장소 미포함), 이 문서의 명세와 같은 구조입니다.

## 1. 원본 서식 취급

학교에서 받은 원본 서식은 **내부 자료라 저장소에 포함하지 않습니다.**
다만 서식 전체를 막으면 공개 가능한 다른 서식까지 걸리므로, **내부용 폴더 이름 하나만** 제외합니다.

```gitignore
ysu_forms/     # 원본 + 그 파생물 전부
```

이게 가능한 이유는 변환·추출 결과가 **원본 경로를 그대로 미러링**하기 때문입니다.

| 경로 | 내용 | 재생성 방법 |
|---|---|---|
| `forms/ysu_forms/…` | 원본 서식 (HWP/XLSX/PDF) | 배포 불가. 로컬에 직접 배치 |
| `templates/ysu_forms/…` | 원본을 변환한 HWPX 템플릿 | `tools/convert_templates.py` |
| `schemas/ysu_forms/…` | 서식 구조 스키마 JSON + 목록 | `tools/extract_schema.py` |
| `out/` | 생성된 문서 산출물 | 실행 결과 |
| `data/` | 서비스 DB, 서식 버전별 템플릿, 문서 산출물 | `tools/sync_forms.py` 후 웹 API 사용 결과 |

템플릿과 스키마는 원본 서식의 문구를 그대로 담기 때문에 원본과 동일하게 취급합니다.
서식 목록(`index.json`)도 서식 이름을 담으므로 최상위가 아니라 각 원본 폴더 안에 둡니다.
내부용이 아닌 서식을 `forms/` 아래 다른 이름으로 넣으면, 그 파생물은 정상적으로 커밋됩니다.

## 2. 서식 구조 분석 결과 (설계 근거)

원본 서식(HWP 5.0 / OLE-CFB)을 해부해 확인한 사실이 설계를 결정했습니다.

**① 누름틀은 기안문 계열에만 풍부하다**

기안문·지출품의서는 전자문서 표준 서식이라 **이름이 붙은 누름틀**이 심어져 있습니다.
`docnumber`, `enforcedate`, `apb1_type`/`apb1_date`/`apb1_sign` … `apb8_*`, `zipcode`, `address`,
`telephone`, `email`, `content_body` 등이며, **`apbN_*` 가 결재란**이라 향후 결재선 자동화의 직접 주입 지점이 됩니다.

**② 그 외 서식은 사실상 표(table)가 전부다**

계획서·보고서·정산서·내역서 계열은 고유 누름틀이 1종뿐이거나 아예 없고, 내용이 전부 표 셀 안에 있습니다.
분석한 서식 183개 중 **46%(85개)가 누름틀 0개**였습니다. 따라서 **표 셀 채우기가 주 메커니즘**이고 누름틀은 보조입니다.

**③ 채울 지점은 자리표시자가 알려준다**

서식에는 `○○○○○과`, `재학생 00명`, `2000.00.00`, `0,000,000원`, `□현장견학` 같은 자리표시자가 박혀 있습니다.
이게 "채워야 할 곳"의 가장 확실한 신호라, 인접 셀 추론보다 우선해서 사용합니다.

**④ 명단·내역은 반복 행 영역이다**

출석부·지급내역서는 헤더 행 + 예시 행 + 빈 행 수십 줄 구조입니다.
빈 셀을 하나씩 입력 지점으로 잡으면 한 장에 350개가 나오므로, **반복 영역 하나**로 묶습니다.
예시 행(`1 / 홍길동 / 2000000000`)이 헤더 바로 위에 붙어 있어, 자리표시자 포함 여부로 진짜 헤더와 구분합니다.

이 구조는 HWPX(zip+XML)로 변환하면 그대로 드러납니다.

```xml
<hp:ctrl><hp:fieldBegin id="1298154009" type="CLICK_HERE" name="docnumber" .../></hp:ctrl>
<hp:t>○○○○처-000000</hp:t>
<hp:ctrl><hp:fieldEnd beginIDRef="1298154009" .../></hp:ctrl>
```

`fieldBegin.id` ↔ `fieldEnd.beginIDRef` 로 짝을 짓고, 그 사이 `<hp:t>` 가 값입니다.
표는 `hp:tbl` → `hp:tr` → `hp:tc` 에 `cellAddr`(좌표)와 `cellSpan`(병합)이 붙습니다.

## 3. 아키텍처 결정

### 3.1 HWP 처리 — 하이브리드
- **주 경로(순수 파이썬)**: 템플릿을 HWPX로 1회 변환해 두고, 값 주입은 zip+XML 조작으로 처리.
  한컴오피스 없이 동작하고, 테스트·diff가 가능하며, 서버 이전이 쉽습니다.
- **보조 경로(로컬 전용)**: 원본 변환과 최종 `.hwp` / `.pdf` 산출은 한컴 COM 사용.

> **왜 이렇게 나눴나**: 한컴 COM은 Windows + 한컴오피스가 깔린 기기에서만 동작해 AWS로 못 올라갑니다.
> COM 의존을 `docflow/adapters/hancom.py` 한 곳에 가둬 두면, Phase 2에서 이 모듈만 떼거나
> 별도 Windows 워커로 분리하면 됩니다. 코어(`docflow/hwpx`)는 COM을 import 하지 않습니다.

### 3.2 생성·검증 — LLM 하이브리드
| 구분 | 담당 | 이유 |
|---|---|---|
| 필수항목 누락, 금액 합계, 날짜 형식·순서, 문서 간 금액 일치 | **규칙 코드** | 재현성·속도·비용. 결재 문서라 같은 입력에 다른 결과가 나오면 안 됨 |
| 프롬프트로 서식 칸 채우기, 본문 문안 생성, 규정 해석이 필요한 정성 검증 | **LLM** | 자연어 해석과 공문 문체가 필요한 영역. 결과는 사용자가 확인하고 규칙 검증을 그대로 거친다 |
| 학생 명단·계좌 (입금계좌 확인서 HWP 읽기) | **규칙 코드** | 한 자리만 틀려도 안 되는 값이고 개인정보라 LLM 에 넘기지 않는다 |

### 3.3 LLM — 로컬 실행
개인정보가 외부로 나가지 않도록 **로컬 LLM**을 사용합니다. 그래도 학생 명단·계좌번호·주민등록번호는 LLM 에 넘기지 않고,
학생에게 받은 입금계좌 확인서(HWP)를 읽어 채우거나 직접 입력합니다.
**EXAONE 3.5 7.8B**를 사용합니다 (한국어 네이티브, 개발 장비 RTX 3060 12GB에 Q4/Q5 양자화로 적재 가능).
비상업/연구 목적 라이선스라 캡스톤 용도에는 부합하며, 실제 도입 시에는 재검토가 필요합니다.

### 3.4 검증 기준 주입 — 자리표시자에서 규칙을 유도한다
지침·서식을 한 번 분석해 **서식별 검증 규칙**을 만들어 두고, 런타임에는 그 규칙만 씁니다.
매번 지침 문서를 RAG로 검색하는 방식보다 저렴·빠르고, 규칙이 코드로 남아 **감사(audit)가 가능**합니다.

규칙의 근거는 **자리표시자**입니다. 슬롯이 4,953개라 체크리스트를 손으로 채울 수 없고,
그럴 필요도 없습니다 — `2000.00.00` 은 날짜 칸이고 `5,000` 은 금액 칸이며 `합계` 는 합계 칸이라고
서식이 스스로 알려주기 때문입니다. 판정은 `docflow/schema/rules.py` 에 모여 있습니다.

| 판정 | 무엇을 보나 |
|---|---|
| `is_placeholder` | 채워야 할 칸인가 (`○○○`, `0,000,000`, `□`) |
| `is_date_placeholder` | 칸 **전체**가 날짜인가 (`2000.00.00(금)`) |
| `is_total_label` | 합계 행인가 (`합계`, `소계`) |

`is_date_placeholder` 가 칸 전체를 보는 이유는, `○○○○처-000000 2000.00.00` 처럼 문서번호가
붙은 칸을 날짜 칸으로 오인하면 문서번호를 적을 때마다 오류가 나기 때문입니다.

### 3.5 결재 자동화 범위
- **지금**: 문서 생성 + 서식 검증
- **나중**: 결재 라인 자동 진행, 참조/첨부/서식 부적합 판단 → 반려/통과 구분

### 3.6 사용자·관리자와 로그인
- **사용자(작성자)**: 서식 선택 → 입력 → 검증 → 수정 → 변환 → 다운로드. 문서 생성은 사용자가 합니다.
- **관리자**: 사용자가 쓸 서식·입력폼·검증 규칙을 준비하고 계정·시스템을 운영합니다. 사용자 권한도 포함합니다.
- **로그인은 IAM 방식**입니다. 관리자가 아이디와 초기 비밀번호를 발급하고, 사용자는 그 아이디로만 이용합니다.
  가입 신청과 비밀번호 찾기는 없고(분실 시 관리자가 초기화), 첫 로그인 때 비밀번호 변경을 강제합니다.
- 문서는 계정별로 따로 보관합니다. **사업별(앵커/AID/혁신) 접근 제한은 없습니다.**

## 4. 파이프라인

```
forms/<원본폴더>/**/*.hwp        원본 서식
    | tools/convert_templates.py        [한컴 COM]
templates/<원본폴더>/**/*.hwpx   편집 가능한 XML 템플릿 (원본 경로 미러링)
    | tools/extract_schema.py           [순수 파이썬]
schemas/<원본폴더>/**/*.json     필드 / 표 / 슬롯 / 반복영역 + 검증 체크리스트
    | tools/sync_forms.py               서식·버전 등록 (DB + data/)
    | 입력값 -> validate -> generate      [순수 파이썬]  (LLM 문안 생성은 M10)
문서.hwpx
    | docflow/convert.py  변환 요청/결과
    | docflow/adapters/hancom.py        [한컴 COM · 자식 프로세스]
문서.hwp, 문서.pdf                 내려받기: 서식번호_문서명_작성일
```

## 5. 디렉터리 구조

```
DocFlow/
├─ docflow/
│  ├─ hwpx/document.py     # HWPX 읽기·쓰기(누름틀 + 표 셀 + 반복영역 행), 플랫폼 무관
│  ├─ hwpx/formula.py      # 표 수식 해석·재계산
│  ├─ schema/model.py      # 서식 스키마 모델 (v2)
│  ├─ schema/rules.py      # 자리표시자·합계·날짜 판정 (순수 함수)
│  ├─ schema/extract.py    # HWPX -> 스키마 추출기
│  ├─ validate.py          # 규칙 기반 검증 엔진 (칸 단위·문서 단위)
│  ├─ generate.py          # 입력값 -> HWPX (결재란 비우기·반복 행 정리·변형 선택·남은 자리표시자 경고)
│  ├─ pipeline.py          # 입력 JSON 해석 -> 검증 -> 생성 -> 변환 (CLI·웹이 함께 쓴다)
│  ├─ convert.py           # 형식 변환 요청/결과 인터페이스 (변환기와 무관)
│  ├─ service/             # DB 모델·서식 목록(버전)·문서 서비스·파일 저장소·로그인(auth)
│  ├─ web/app.py           # FastAPI (/api)
│  ├─ config.py · log.py   # 경로·환경 설정, 로깅
│  └─ adapters/hancom.py   # 한컴 COM 어댑터 (로컬 전용, 격리 대상)
├─ tools/
│  ├─ convert_templates.py # 원본 .hwp -> .hwpx 일괄 변환
│  ├─ extract_schema.py    # HWPX -> 서식 스키마 JSON 추출
│  ├─ make_document.py     # 서식 하나를 입력 JSON 으로 채워 HWPX·HWP·PDF 로 (M5)
│  ├─ sync_forms.py        # templates/ 의 서식을 서비스 DB 에 등록 (M6)
│  └─ manage_users.py      # 루트 관리자 만들기·잠금 해제·비밀번호 초기화 (M7)
├─ tests/                  # pytest. 기본은 내부 자료 없이, 실제 서식 회귀는 `-m local`
├─ docs/index.html         # 진행 현황 리포트 (GitHub Pages)
├─ docs/functional-spec.md # 기능명세서 (역할·메뉴 Depth·기능 상세)
└─ requirements.txt
```

### 스키마가 담는 것
| 항목 | 설명 |
|---|---|
| `fields` | 누름틀. 이름·타입·등장 횟수·원래 값 |
| `tables` | 표별 행/열/중첩깊이와 병합을 펼친 텍스트 격자 |
| `slots` | 채워야 할 셀. `origin`: `placeholder`(자리표시자가 있던 셀) / `empty`(항목명이 붙은 빈 셀), `role`: 작성자 입력 / 결재란 |
| `repeats` | 명단·내역의 반복 행 영역. 열 이름과 수용 행 수 |
| `formulas` | 수식 칸. 작성자가 아니라 우리가 다시 계산해 쓴다 |
| `variants` | 한 파일에 여러 서식이 든 경우(기안문·지출품의서) 변형별 표 범위 |
| `checklist` | 검증 규칙. 이후 단계에서 채움 |

## 6. 개발 로드맵

기능명세 기준으로 다시 짜는 중이며, 자세한 계획은 [`docs/dev-roadmap.md`](docs/dev-roadmap.md)에 있습니다.
진행도는 마일스톤 규모(S=1, M=2, L=3) 가중 **67%** (2026-10-24, M10 을 L 로 키워 30점 기준).
입력의 기본 방식을 프롬프트 → LLM 이 칸을 채움 → 확인으로 바꿔 M10 을 M9 보다 먼저 합니다.

|---|---|---|:-:|
| M0 | 기반 (테스트·린트·설정·로깅) | 테스트·린트가 한 명령으로 돈다 | ✅ |
| M1 | HWPX 코어 — 누름틀·표 셀·반복영역 쓰기 | 서식 193개 쓰기 → 저장 → 재읽기 일치 | ✅ |
| M2 | 서식 파이프라인 — 변환·스키마 추출 | 변환 193 / 추출 183, 실패 0 | ✅ |
| M3 | 검증 엔진 | 규칙 4종, 올바른 입력에서 오탐 0 | ✅ |
| M4 | 변환 어댑터 — HWP·PDF | 산출물이 한글에서 열림, 비정상 종료 후에도 다음 변환 진행 | ✅ |

### 검증 엔진

`docflow/validate.py`. 입력값을 받아 위반 사항 목록을 돌려줍니다. 같은 규칙을 **칸 단위**(실시간 점검)와
**문서 단위**(입력 완료 검증) 두 가지로 부릅니다. 누름틀 값은 `HwpxDocument.fill()` 과 같은 형태라 그대로 주입에 넘깁니다.

```python
validate(schema, FormInput(cells=..., fields=..., rows=...), config) -> list[Issue]
check_cell(...) / check_field(...) / check_repeat_cell(...)   # 칸 하나
```

| 규칙 | 코드 | 적용 서식 | 검사 대상 |
|---|---|---:|---|
| 필수 누락 | `REQUIRED_EMPTY` | 183 / 183 | 표 필수 칸 2,122 + 누름틀 90 |
| 날짜 | `DATE_INVALID` `DATE_ORDER` | 107 / 183 | 날짜 칸 143 + 누름틀 30 + 반복영역 날짜 열 25 |
| 금액 합계 | `AMOUNT_TOTAL_MISMATCH` | 49 / 183 | 작성자가 적는 합계 칸 99 |

규칙 on/off·무시할 자리·심각도는 `ValidationConfig` 로 받고, 서식별 예외를 덧씌울 수 있습니다(관리자 규칙 관리 대비).

**무엇을 일부러 빼는가** — 오탐을 줄이는 쪽이 중요합니다. 결재 문서라 틀린 경고가 나오면 아무도 안 봅니다.
제외 항목은 `Exclusions` 설정으로 명시돼 있어 끌 수 있습니다.

| 제외 | 개수 | 이유 |
|---|---:|---|
| 항목명만 보고 잡은 빈 칸 (`origin="empty"`) | 1,935 | 인접 셀 추론이라 첨부 확인란처럼 안 채우는 게 정상인 칸이 섞임 |
| 반복영역에서 입력하지 않은 행 | — | 명단은 수용 행을 다 채우지 않는 게 정상 |
| 수식 칸 | 305 | 우리가 다시 계산해 쓰므로 틀릴 수 없음 |
| 결재란 (칸 + `apbN_*` 누름틀) | 896 + 312 | 작성자가 아니라 결재선이 채우는 자리 (3.5) |

결재란은 빼지 않으면 **규칙이 아니라 우연이 됩니다**. `apb4_date` 는 템플릿에 `00/00` 이
남아 있어 필수로 잡히는데 `apb1_date` 는 공백이라 안 잡힙니다. 같은 성격의 칸이 예시 글자가
남았는지로 갈리는 셈입니다.

**함정 세 가지**

`2024.5.2.(목) 13:00~17:00` 의 물결은 기간이 아니라 **시각**을 나눕니다. 물결로 쪼개면 뒷조각에
날짜가 없어 오탐이 납니다. 그래서 값에서 날짜만 뽑아 연속된 것끼리 순서를 봅니다.

금액 합계는 반복영역의 합계 행이면 **입력한 행들**의 같은 열을 더하고, 그 밖(항목이 행마다 고정된 정산표 등)이면
같은 열에서 직전 합계 다음 칸부터 더합니다. 소계와 합계가 같이 있는 표도 이 방식이면 구간이 맞습니다.

합계에 더하는 값은 **칸 전체가 금액인 칸**뿐입니다. 연번·수량·날짜 칸까지 더해 `2026.10.12` 가
`2026원`으로 합산되는 오탐이 옛 엔진에 있었습니다.

```
테스트   516개 (기본 493 + 로컬 23)
```

기본 테스트는 서식 파일을 읽지 않고 스키마·HWPX를 코드로 만듭니다. 원본이 내부 자료라 저장소에 없기
때문이고, 덕분에 클론한 사람도 바로 돌릴 수 있습니다. 실제 서식과 한컴오피스가 필요한 회귀 테스트는
`pytest -m local` 로 분리했습니다.

### 알려진 함정 — 좀비 한글 프로세스
COM으로 띄운 한글이 `Quit()` 후에도 남는 경우가 있고, 남은 인스턴스에 다음 `Dispatch` 가 붙으면
`Open()` 에서 **무한 대기**합니다 (실제로 배치 변환이 여기서 멈췄습니다).
그래서 `HancomConverter` 는 변환을 **자식 프로세스**에서 돌리고, 시간 초과(기본 60초)면 자식과 그것이 띄운
한글을 끊은 뒤 실패한 형식만 1회 다시 시도합니다. 시도 전에는 창이 없는 한글(자동화가 띄운 고아)만 정리해
사람이 열어 둔 한글은 건드리지 않습니다. 경로가 260자를 넘으면 한글이 저장에 실패하므로 짧은 임시 폴더에서
변환한 뒤 옮깁니다. 보통은 신경 쓸 필요 없지만, 직접 확인하려면:

```powershell
Get-Process Hwp -ErrorAction SilentlyContinue | Select-Object Id, StartTime, MainWindowTitle
# 창 제목이 비어 있으면 자동화가 띄운 고아 프로세스 -> 종료해도 안전
```
