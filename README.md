# DocFlow — 서식 기반 문서 자동 생성 및 검증 시스템

대학 재정지원사업 서식을 기반으로 **문서를 자동 생성하고, 서식·규정 준수 여부를 검증**하는 시스템입니다.
장기적으로는 결재 라인 자동화(반려/통과 판정)까지 확장합니다.

캡스톤 디자인(졸업작품) 프로젝트이며, 현재 **Phase 1 구현 중**입니다.

---

## 1. 원본 서식 취급

학교에서 받은 원본 서식은 **내부 자료라 저장소에 포함하지 않습니다.**
다만 서식 전체를 막으면 공개 가능한 다른 서식까지 걸리므로, **내부용 폴더 이름 하나만** 제외합니다.

```gitignore
ysu_forms/     # 원본 + 그 파생물 전부
```

이게 가능한 이유는 변환·추출 결과가 **원본 경로를 그대로 미러링**하기 때문입니다.

| 경로 | 내용 | 재생성 방법 |
|---|---|---|
| `forms/ysu_forms/…` | 원본 서식 (HWP/XLSX/PDF) | 배포 불가. 로컬에 직접 배치 |
| `templates/ysu_forms/…` | 원본을 변환한 HWPX 템플릿 | `tools/convert_templates.py` |
| `schemas/ysu_forms/…` | 서식 구조 스키마 JSON + 목록 | `tools/extract_schema.py` |
| `out/` | 생성된 문서 산출물 | 실행 결과 |

템플릿과 스키마는 원본 서식의 문구를 그대로 담기 때문에 원본과 동일하게 취급합니다.
서식 목록(`index.json`)도 서식 이름을 담으므로 최상위가 아니라 각 원본 폴더 안에 둡니다.
내부용이 아닌 서식을 `forms/` 아래 다른 이름으로 넣으면, 그 파생물은 정상적으로 커밋됩니다.

## 2. 서식 구조 분석 결과 (설계 근거)

원본 서식(HWP 5.0 / OLE-CFB)을 해부해 확인한 사실이 설계를 결정했습니다.

**① 누름틀은 기안문 계열에만 풍부하다**

기안문·지출품의서는 전자문서 표준 서식이라 **이름이 붙은 누름틀**이 심어져 있습니다.
`docnumber`, `enforcedate`, `apb1_type`/`apb1_date`/`apb1_sign` … `apb8_*`, `zipcode`, `address`,
`telephone`, `email`, `content_body` 등이며, **`apbN_*` 가 결재란**이라 향후 결재선 자동화의 직접 주입 지점이 됩니다.

**② 그 외 서식은 사실상 표(table)가 전부다**

계획서·보고서·정산서·내역서 계열은 고유 누름틀이 1종뿐이거나 아예 없고, 내용이 전부 표 셀 안에 있습니다.
분석한 서식 183개 중 **46%(85개)가 누름틀 0개**였습니다. 따라서 **표 셀 채우기가 주 메커니즘**이고 누름틀은 보조입니다.

**③ 채울 지점은 자리표시자가 알려준다**

서식에는 `○○○○○과`, `재학생 00명`, `2000.00.00`, `0,000,000원`, `□현장견학` 같은 자리표시자가 박혀 있습니다.
이게 "채워야 할 곳"의 가장 확실한 신호라, 인접 셀 추론보다 우선해서 사용합니다.

**④ 명단·내역은 반복 행 영역이다**

출석부·지급내역서는 헤더 행 + 예시 행 + 빈 행 수십 줄 구조입니다.
빈 셀을 하나씩 입력 지점으로 잡으면 한 장에 350개가 나오므로, **반복 영역 하나**로 묶습니다.
예시 행(`1 / 홍길동 / 2000000000`)이 헤더 바로 위에 붙어 있어, 자리표시자 포함 여부로 진짜 헤더와 구분합니다.

이 구조는 HWPX(zip+XML)로 변환하면 그대로 드러납니다.

```xml
<hp:ctrl><hp:fieldBegin id="1298154009" type="CLICK_HERE" name="docnumber" .../></hp:ctrl>
<hp:t>○○○○처-000000</hp:t>
<hp:ctrl><hp:fieldEnd beginIDRef="1298154009" .../></hp:ctrl>
```

`fieldBegin.id` ↔ `fieldEnd.beginIDRef` 로 짝을 짓고, 그 사이 `<hp:t>` 가 값입니다.
표는 `hp:tbl` → `hp:tr` → `hp:tc` 에 `cellAddr`(좌표)와 `cellSpan`(병합)이 붙습니다.

## 3. 아키텍처 결정

### 3.1 HWP 처리 — 하이브리드
- **주 경로(순수 파이썬)**: 템플릿을 HWPX로 1회 변환해 두고, 값 주입은 zip+XML 조작으로 처리.
  한컴오피스 없이 동작하고, 테스트·diff가 가능하며, 서버 이전이 쉽습니다.
- **보조 경로(로컬 전용)**: 원본 변환과 최종 `.hwp` / `.pdf` 산출은 한컴 COM 사용.

> **왜 이렇게 나눴나**: 한컴 COM은 Windows + 한컴오피스가 깔린 기기에서만 동작해 AWS로 못 올라갑니다.
> COM 의존을 `docflow/adapters/hancom.py` 한 곳에 가둬 두면, Phase 2에서 이 모듈만 떼거나
> 별도 Windows 워커로 분리하면 됩니다. 코어(`docflow/hwpx`)는 COM을 import 하지 않습니다.

### 3.2 생성·검증 — LLM 하이브리드
| 구분 | 담당 | 이유 |
|---|---|---|
| 필수항목 누락, 금액 합계, 날짜 형식·순서, 문서 간 금액 일치 | **규칙 코드** | 재현성·속도·비용. 결재 문서라 같은 입력에 다른 결과가 나오면 안 됨 |
| 본문 문안 생성, 규정 해석이 필요한 정성 검증 | **LLM** | 지침 해석과 자연스러운 공문 문체가 필요한 영역 |

### 3.3 LLM — 로컬 실행
학생 명단·계좌번호 등 개인정보가 외부로 나가지 않도록 **로컬 LLM**을 사용합니다.
후보는 **EXAONE 3.5 7.8B** (한국어 네이티브, 개발 장비 RTX 3060 12GB에 Q4/Q5 양자화로 적재 가능).
비상업/연구 목적 라이선스라 캡스톤 용도에는 부합하며, 실제 도입 시에는 재검토가 필요합니다.

### 3.4 검증 기준 주입 — 자리표시자에서 규칙을 유도한다
지침·서식을 한 번 분석해 **서식별 검증 규칙**을 만들어 두고, 런타임에는 그 규칙만 씁니다.
매번 지침 문서를 RAG로 검색하는 방식보다 저렴·빠르고, 규칙이 코드로 남아 **감사(audit)가 가능**합니다.

규칙의 근거는 **자리표시자**입니다. 슬롯이 8,904개라 체크리스트를 손으로 채울 수 없고,
그럴 필요도 없습니다 — `2000.00.00` 은 날짜 칸이고 `5,000` 은 금액 칸이며 `합계` 는 합계 칸이라고
서식이 스스로 알려주기 때문입니다. 판정은 `docflow/schema/form.py` 에 모여 있습니다.

| 판정 | 무엇을 보나 |
|---|---|
| `is_placeholder` | 채워야 할 칸인가 (`○○○`, `0,000,000`, `□`) |
| `is_date_placeholder` | 칸 **전체**가 날짜인가 (`2000.00.00(금)`) |
| `is_total_label` | 합계 행인가 (`합계`, `소계`) |

`is_date_placeholder` 가 칸 전체를 보는 이유는, `○○○○처-000000 2000.00.00` 처럼 문서번호가
붙은 칸을 날짜 칸으로 오인하면 문서번호를 적을 때마다 오류가 나기 때문입니다.

### 3.5 결재 자동화 범위
- **지금**: 문서 생성 + 서식 검증
- **나중**: 결재 라인 자동 진행, 참조/첨부/서식 부적합 판단 → 반려/통과 구분

## 4. 파이프라인

```
forms/<원본폴더>/**/*.hwp        원본 서식
    | tools/convert_templates.py        [한컴 COM]
templates/<원본폴더>/**/*.hwpx   편집 가능한 XML 템플릿 (원본 경로 미러링)
    | tools/extract_schema.py           [순수 파이썬]
schemas/<원본폴더>/**/*.json     필드 / 표 / 슬롯 / 반복영역 + 검증 체크리스트
    | 입력값 + LLM 문안 생성
    | docflow/hwpx  값 주입              [순수 파이썬]
out/*.hwpx
    | docflow/adapters/hancom.py        [한컴 COM]
out/*.hwp, out/*.pdf
```

## 5. 디렉터리 구조

```
DocFlow/
├─ docflow/
│  ├─ hwpx/document.py     # HWPX 읽기·쓰기 (누름틀 + 표), 플랫폼 무관
│  ├─ schema/form.py       # 서식 스키마 모델 + 자리표시자 판별
│  ├─ validate.py          # 규칙 기반 검증 엔진
│  └─ adapters/hancom.py   # 한컴 COM 어댑터 (로컬 전용, 격리 대상)
├─ tools/
│  ├─ convert_templates.py # 원본 .hwp -> .hwpx 일괄 변환
│  └─ extract_schema.py    # HWPX -> 서식 스키마 JSON 추출
├─ tests/                  # pytest. 내부 자료에 의존하지 않는다
├─ docs/index.html         # 진행 현황 리포트 (GitHub Pages)
└─ requirements.txt
```

### 스키마가 담는 것
| 항목 | 설명 |
|---|---|
| `fields` | 누름틀. 이름·타입·등장 횟수·원래 값 |
| `tables` | 표별 행/열/중첩깊이와 병합을 펼친 텍스트 격자 |
| `slots` | 채워야 할 셀. `placeholder`(자리표시자가 있던 셀) / `empty`(항목명이 붙은 빈 셀) |
| `repeats` | 명단·내역의 반복 행 영역. 열 이름과 수용 행 수 |
| `checklist` | 검증 규칙. 5·6단계에서 채움 |

## 8. 현재까지 검증된 것

대상은 앵커(신산업)·AID·혁신 3개 사업의 서식 전체입니다.
서식이 아닌 문서(서식 목차 9건, 서식 신구대조표 1건)는 제외했습니다.

```
템플릿 변환      .hwp 193개 -> .hwpx 변환, 실패 0
스키마 추출      서식 183개 전부 추출, 실패 0
                 누름틀 630  표 2,501  슬롯 8,904  반복영역 281
누름틀 파싱      기안문·품의서 계열 15개 서식에서 누름틀 547개 / 고유 51종
표 파싱          중첩 표 포함 좌표·병합·셀 텍스트 추출
쓰기 라운드트립  값 주입 -> 저장 -> 재읽기 값 일치
산출물          생성한 .hwpx 를 한글이 정상적으로 열고 .hwp / .pdf 로 변환 성공
커버리지         슬롯과 반복영역이 둘 다 0인 서식 0개
                 = 183개 전부 채울 지점을 찾아냄
```

사업별 내역:

| 사업 | 서식 | 누름틀 | 표 | 슬롯 | 반복영역 |
|---|---:|---:|---:|---:|---:|
| 혁신 | 94 | 333 | 1,383 | 4,912 | 158 |
| AID | 45 | 167 | 630 | 2,322 | 63 |
| 앵커(신산업) | 38 | 130 | 479 | 1,652 | 45 |
| 미분류 | 6 | 0 | 9 | 18 | 15 |

미분류 6건은 행정지원처의 `성범죄 경력 조회 동의서`(부서용/회신용)로, 외부 기관 양식이라
서식 번호가 없습니다. AID·혁신에 중복 배포되어 있어 실질 2종입니다.

### 검증 엔진 (5단계)

`docflow/validate.py`. 입력값을 받아 위반 사항 목록을 돌려줍니다. 표 셀과 누름틀을 따로 받는데,
`HwpxDocument.fill()` 이 누름틀 이름을 키로 받기 때문에 나중에 그대로 주입에 넘길 수 있습니다.

```python
validate(schema, values, fields=None) -> list[Issue]
#               ^표 셀    ^누름틀
```

| 규칙 | 코드 | 적용 서식 | 검사 대상 |
|---|---|---:|---|
| 필수 누락 | `REQUIRED_EMPTY` | 177 / 183 | 표 자리표시자 칸 4,610 + 누름틀 90 |
| 금액 합계 | `AMOUNT_TOTAL_MISMATCH` | 78 / 183 | 합계 셀 298 |
| 날짜 | `DATE_INVALID` `DATE_ORDER` | 95 / 183 | 날짜 칸 191 + 누름틀 15 |

**무엇을 일부러 빼는가** — 오탐을 줄이는 쪽이 중요합니다. 결재 문서라 틀린 경고가 나오면 아무도 안 봅니다.

| 제외 | 개수 | 이유 |
|---|---:|---|
| 항목명만 보고 잡은 빈 칸 (`kind="empty"`) | 4,177 | 인접 셀 추론이라 첨부 확인란처럼 안 채우는 게 정상인 칸이 섞임 |
| 반복 영역 안의 자리표시자 칸 | 168 | 명단은 수용 행을 다 채우지 않는 게 정상 |
| 이름 없는 수식 누름틀 (`FORMULA`) | 305 | 한글이 스스로 계산. 이름이 없어 키로 쓸 수도 없음 |
| 결재란 (`apbN_*`) | 90 | 작성자가 아니라 결재선이 채우는 자리 (3.5) |

마지막 항목은 빼지 않으면 **규칙이 아니라 우연이 됩니다**. `apb4_date` 는 템플릿에 `00/00` 이
남아 있어 필수로 잡히는데 `apb1_date` 는 공백이라 안 잡힙니다. 같은 성격의 칸이 예시 글자가
남았는지로 갈리는 셈입니다.

**함정 두 가지**

`2024.5.2.(목) 13:00~17:00` 의 물결은 기간이 아니라 **시각**을 나눕니다. 물결로 쪼개면 뒷조각에
날짜가 없어 오탐이 납니다. 그래서 값에서 날짜만 뽑아 연속된 것끼리 순서를 봅니다.

금액 합계는 **반복 영역을 기준으로 삼지 않습니다**. 명단 첫 줄이 예시 행(`홍길동`)이라 반복
영역에서 빠지기 때문입니다. 교통비 내역서는 데이터가 7~16행인데 반복 영역이 8~16행이라,
그대로 더하면 45,000 이 나와 합계 50,000 과 안 맞습니다. 대신 합계 셀의 열에서 직전 합계
다음 행부터 셉니다.

```
테스트   35개 통과 (pytest)
```

테스트는 서식 파일을 읽지 않고 스키마를 코드로 만듭니다. 원본이 내부 자료라 저장소에 없기
때문이고, 덕분에 클론한 사람도 바로 돌릴 수 있습니다.

### 알려진 함정 — 좀비 한글 프로세스
COM으로 띄운 한글이 `Quit()` 후에도 남는 경우가 있고, 남은 인스턴스에 다음 `Dispatch` 가 붙으면
`Open()` 에서 **무한 대기**합니다 (실제로 배치 변환이 여기서 멈췄습니다).
`Hancom.close()` 가 자신이 띄운 PID를 추적해 강제 정리하므로 보통은 신경 쓸 필요 없지만,
비정상 종료 후 변환이 멈추면 확인하세요:

```powershell
Get-Process Hwp -ErrorAction SilentlyContinue | Select-Object Id, StartTime, MainWindowTitle
# 창 제목이 비어 있으면 자동화가 띄운 고아 프로세스 -> 종료해도 안전
```
